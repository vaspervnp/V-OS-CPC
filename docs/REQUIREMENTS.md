# V-OS για Amstrad CPC 6128: τι απαιτείται

Το έγγραφο περιγράφει τι χρειάζεται για ένα πλήρες γραφικό λειτουργικό σύστημα σε Z80 assembly για τον Amstrad CPC 6128, με:

- οθόνη overscan σε mode 0 και mode 1 (και προαιρετικά μικτή),
- απλό σύστημα μενού που χειρίζεται AMX mouse και πληκτρολόγιο (cursor keys, TAB, συντομεύσεις),
- API για προγράμματα που γράφονται σε γλώσσα τύπου Scratch και μεταφράζονται σε assembly,
- δικό του driver δισκέτας για ανάγνωση και εγγραφή προγραμμάτων.

Τα πρότυπα interface βρίσκονται στο `docs/interface-templates.html`.

---

## 1. Υλικό-στόχος

| Στοιχείο | Λεπτομέρειες | Τι σημαίνει για το V-OS |
|---|---|---|
| CPU | Z80A, 4 MHz (πρακτικά ~3,3 MHz λόγω wait states, κάθε εντολή στρογγυλεύεται σε πολλαπλάσιο 4 T-states / 1 µs) | Μετράμε χρόνο σε «NOPs» (µs). Οι ρουτίνες γραφικών πρέπει να είναι ξετυλιγμένες και με lookup tables. |
| RAM | 128K: 64K βασική + 64K επιπλέον σε 4 banks των 16K | Οι επιπλέον banks εμφανίζονται στο παράθυρο `&4000–&7FFF` μέσω της θύρας `&7Fxx` (configurations `&C4–&C7`). |
| Βίντεο | CRTC 6845 + Gate Array, 27 χρώματα hardware | Overscan ρυθμίζεται από τους καταχωρητές του CRTC. Οι αλλαγές mode και παλέτας γίνονται από το Gate Array. |
| CRTC | Τύποι 0, 1, 2 στα 6128 (3/4 στα Plus) | Η συμπεριφορά στο overscan και στα raster tricks διαφέρει ανά τύπο. Πρέπει να δοκιμαστούν όλοι. |
| Ήχος/πληκτρολόγιο | AY-3-8912 μέσω PPI 8255 | Το πληκτρολόγιο και το joystick διαβάζονται μέσω του AY (καταχωρητής 14) και του PPI. |
| Δισκέτα | NEC µPD765A (FDC), εσωτερικός οδηγός 3" + προαιρετικός B: | Χωρίς DMA και χωρίς interrupt: μεταφορά byte-byte με polling, κρίσιμη στο χρόνο. |
| ROM | Lower ROM (firmware), BASIC, AMSDOS | Το V-OS απενεργοποιεί τις ROM και τρέχει μόνο από RAM. Δεν χρησιμοποιεί firmware. |

Ο CPC 6128 Plus (ASIC, hardware sprites, split screen) μπορεί να υποστηριχθεί αργότερα, αλλά ο στόχος είναι ο απλός 6128.

## 2. Οθόνη: overscan, modes, raster split

### 2.1 Overscan

- Μνήμη οθόνης: **384×272** σε mode 1 (4 χρώματα), **192×272** σε mode 0 (16 χρώματα).
- **Ωφέλιμη περιοχή: 384×259 / 192×259.** Η οθόνη δείχνει 271 γραμμές, και οι 6 πρώτες και οι 6 τελευταίες δεν χρησιμοποιούνται. Το y=0 των γραφικών είναι η φυσική γραμμή 6 και το y=258 η φυσική γραμμή 264 (`GFX_TOP`, `GFX_H` στο `memmap.inc`). Το `gfx_cls` καθαρίζει και τα περιθώρια.
- Μνήμη: 96 bytes ανά γραμμή × 272 = **26.112 bytes**. Η κανονική οθόνη του CPC έχει μόνο 16K, οπότε το overscan απαιτεί **οθόνη 32K** που περνά από το ένα 16K block στο επόμενο (ρύθμιση των bits μεγέθους στον R12 του CRTC).
- Τιμές CRTC (M1): `R0=63, R1=48, R2=50, R3=#8E, R4=38, R6=34, R7=35, R9=7`, `R12/R13=#2C10`. Τα bits MA11–10 = 1 κάνουν το κρατούμενο του MA9 να περνά στη σελίδα `#C000`. Η αρχή στη λέξη 16 κάνει το πέρασμα να συμβαίνει ακριβώς ανάμεσα στις γραμμές χαρακτήρων 20 και 21, ώστε καμία γραμμή pixel να μη σπάει ανάμεσα σε δύο σελίδες. Γραμμές 0–20 στο `#8020 + row*96`, γραμμές 21–33 στο `#C000 + (row-21)*96`, συν `line*#800`.
- Επαληθεύτηκε στον Caprice32 (6128). **Μένει δοκιμή σε όλους τους τύπους CRTC και σε πραγματικό μηχάνημα.** Οι γραμμές εκτός ωφέλιμης περιοχής δεν σχεδιάζονται ποτέ από το UI.
- Τα 6.656 bytes που περισσεύουν μέσα στο 32K (`#8000–#801F` και `#C4E0–#C7FF`, το καθένα συν `line*#800` για τις 8 γραμμές pixel, βλ. `src/include/memmap.inc`) χρησιμοποιούνται για buffers. Από το M4 τα κενά `GAP0–GAP7` (800 bytes το καθένα, στο `#C4E0 + n*#800`) κρατούν τη γραμματοσειρά και τους πίνακες του language pack, το κείμενο των διαλόγων, το buffer sector και τον χάρτη blocks του δίσκου, τον κατάλογο (64 εγγραφές) και τη λίστα αρχείων του UI. Ο χάρτης είναι στο `memmap.inc`.
- Δεν υπάρχει χώρος για double buffering ολόκληρης οθόνης. Χρειάζεται σχεδίαση με dirty rectangles και αποθήκευση του φόντου κάτω από τον δείκτη.

### 2.2 Modes και παλέτα

- Συνάρτηση αλλαγής mode για όλη την οθόνη (mode 0/1) με ταυτόχρονη αλλαγή παλέτας.
- Η κωδικοποίηση pixel διαφέρει ανά mode (στο mode 0 τα bits των 2 pixels είναι πλεγμένα, στο mode 1 των 4 pixels). Χρειάζονται πίνακες μετατροπής (ink → byte mask) για κάθε mode.
- Ξεχωριστά σετ ρουτινών γραφικών ανά mode, με κοινό API (το πρόγραμμα ζητά «ink 3», το σύστημα ξέρει πώς γράφεται).

### 2.3 Μικτή οθόνη (πρότυπο D)

- Ο Gate Array δίνει interrupt κάθε 52 γραμμές HSYNC (6 ανά frame, 300 Hz). Η αλλαγή mode σε συγκεκριμένη γραμμή γίνεται μέσα στο interrupt handler με χρονισμένη αναμονή.
- Ο handler πρέπει να έχει σταθερή διάρκεια, να αλλάζει mode και παλέτα στις ζώνες, και να μην χάνει τον συγχρονισμό όταν τρέχει κώδικας δισκέτας (βλ. §5.4).
- Οι αλλαγές γίνονται στην αρχή της γραμμής. Ό,τι σχεδιάζεται σε μια ζώνη ακολουθεί το mode εκείνης της ζώνης, άρα και τα μενού που «πέφτουν» στη ζώνη mode 0.

**Υλοποίηση M8a** (`src/gfx/split.asm`, `VOS_SPLIT`):
- **Ζώνες:** mode 1, μετά mode 0 από τη γραμμή y1 ως την y2−1, μετά πάλι mode 1. Οι πένες 0–3 έχουν δικά τους χρώματα σε κάθε ζώνη, και οι πένες 4–15 φαίνονται μόνο στη ζώνη mode 0.
- **Χρονισμός** (μετρημένος στον Caprice32):
  - Το interrupt n (1..5) έρχεται στη φυσική γραμμή 27 + 52·(n−1).
  - Το interrupt του VSYNC έρχεται 55 γραμμές πριν από το 1.
  - Το mode διαβάζεται στο HSYNC, γι' αυτό γράφεται στη γραμμή πριν από το όριο.
  - Όριο σε άλλη γραμμή σημαίνει αναμονή 64 µs ανά γραμμή μέσα στο interrupt: 45 γραμμές για y1 = 12, κάτω από τη γραμμή μενού.
- **Δουλειά των 50 Hz:** το πληκτρολόγιο, το ποντίκι, ο δίσκος και ο ήχος πηγαίνουν σε interrupt χωρίς αναμονή (`int_input`). Αλλιώς ο handler ξεπερνούσε το επόμενο interrupt και κάποια frames έχαναν την αλλαγή mode.
- **Σχεδίαση:**
  - Το `gfx_set_mode` δεν αγγίζει τον Gate Array όσο το split είναι ενεργό. Το πρόγραμμα σχεδιάζει κάθε ζώνη με το δικό της mode.
  - Ο kernel σχεδιάζει τη γραμμή μενού σε mode 1 και τα μενού σε mode 0 (`ui_in_band`). Για τα μενού χρειάζεται y1 = 12.
  - Το CLS δίνει πένα 0 στις 13 αχρησιμοποίητες γραμμές πάνω και κάτω από την περιοχή σχεδίασης.
- **Δείκτης:** το x του είναι σε pixels του mode 1, και σχεδιάζεται στο mode της γραμμής του. Στα συμβάντα το x είναι σε pixels της ζώνης. Το `ptr_guard` συγκρίνει πλέον σε bytes οθόνης.

### 2.4 Βιβλιοθήκη γραφικών

- Βασικά: plot, οριζόντια/κάθετη γραμμή, γραμμή Bresenham, γέμισμα ορθογωνίου, πλαίσιο, dither patterns.
- Blit: αντιγραφή ορθογωνίου, sprites με μάσκα (save/restore background), εικονίδια 16×16 / 24×16.
- Κείμενο: γραμματοσειρά 8×8. Οι θέσεις 32–127 (ASCII) είναι πάντα στον kernel, οι θέσεις 128–255 έρχονται από το ενεργό language pack (§6.6). Στο mode 0 προαιρετική στενή γραμματοσειρά 4×8 για περισσότερες στήλες.
- Clipping σε ορθογώνιο (απαραίτητο για παράθυρα και μενού).
- Υπολογισμός διεύθυνσης γραμμής με πίνακα 272 εγγραφών (2 bytes η καθεμία, ~544 bytes) αντί για υπολογισμό κάθε φορά.

## 3. Είσοδος

### 3.1 Πληκτρολόγιο

- Σάρωση του πίνακα 10×8 μέσω PPI/AY, μία φορά ανά frame (ή στα 300 Hz για καλύτερη απόκριση).
- Debounce, auto-repeat με ρυθμιζόμενη καθυστέρηση, ουρά συμβάντων (key down / key up / χαρακτήρας).
- Keymap: αγγλικό πάντα διαθέσιμο, δεύτερη γλώσσα από το language pack (§6.6), εναλλαγή με συνδυασμό πλήκτρων. Modifiers SHIFT, CONTROL, COPY, και dead keys (π.χ. τόνος) που ορίζει το pack.
- Χάρτης πλοήγησης UI: cursor keys, TAB / SHIFT+TAB, RETURN/ENTER, ESC, COPY ως «άνοιγμα μενού», CONTROL+γράμμα ή σκέτο γράμμα για συντομεύσεις μενού.

### 3.2 Ποντίκι (AMX Mouse)

**Απόφαση:** AMX Mouse στη θύρα joystick, χωρίς adapter (υλοποίηση: `src/drivers/mouse.asm`).

- Το AMX Mouse εμφανίζεται ως joystick 0, δηλαδή στη γραμμή 9 του πίνακα πληκτρολογίου:
  - bits 0–3: κινήσεις πάνω, κάτω, αριστερά, δεξιά,
  - bit 5: αριστερό κουμπί (fire 1),
  - bit 4: δεξί κουμπί (fire 2),
  - bit 6: μεσαίο κουμπί.
- Η κίνηση έρχεται ως παλμοί στις γραμμές κατεύθυνσης. Ο driver διαβάζει τη γραμμή 9 σε **κάθε** interrupt (300 Hz) και μετράει τις ανερχόμενες ακμές. Εναλλακτικά (`amx_levels = 1`) μετράει τη στάθμη.
- Όσο το AMX είναι ενεργό, τα πλήκτρα 72–78 (joystick 0) δεν βγάζουν συμβάντα πληκτρολογίου.
- **Μένει να επαληθευτεί σε πραγματικό υλικό:** το πλάτος των παλμών, αν η μέτρηση ακμών δίνει τη σωστή ταχύτητα, και η αντιστοίχιση των κουμπιών. Ο Caprice32 δεν εξομοιώνει AMX.
- Ο ίδιος pointer κινείται ταυτόχρονα και από τα cursor keys, με επιτάχυνση 1→2→4→6 pixels ανά frame. Το COPY λειτουργεί ως αριστερό κουμπί.
- Συμβάντα: `EV_PTR_MOVE` (το πολύ ένα στην ουρά), `EV_PTR_DOWN`, `EV_PTR_UP`, με θέση και κουμπί.
- Δείκτης λογισμικού (`src/gfx/pointer.asm`): βέλος 8×13 με save-under, που κόβεται στις άκρες. Λειτουργεί σε mode 0 και mode 1. Όποιος σχεδιάζει κάτω από τον pointer τον κρύβει πρώτα (`ptr_hide` / `ptr_show`).
- Επιτάχυνση και ταχύτητα θα ρυθμίζονται από το Setup.

### 3.3 Μοντέλο εστίασης και πλοήγησης (υλοποίηση M3: `src/ui/`)

- **Περιγραφή με δεδομένα:** η εφαρμογή περιγράφει τη γραμμή μενού και τα κουμπιά της με πίνακες δεδομένων. Κάθε συμβάν περνά από το `ui_event`, που επιστρέφει αριθμό εντολής (0 = καμία). Ποντίκι, πλήκτρα και συντομεύσεις δίνουν την ίδια εντολή, οπότε η εφαρμογή δεν ξεχωρίζει από πού ήρθε.
- **Μενού:**
  - γραμμή μενού με υπογραμμισμένο το πρώτο γράμμα κάθε τίτλου,
  - πτυσσόμενα μενού με σκιά, διαχωριστικά και συντομεύσεις `^X` στα δεξιά,
  - όλα τα κείμενα από το `lang_msg`, άρα ακολουθούν τη γλώσσα του UI.
- **Πλοήγηση με πλήκτρα:**
  - ESC: ανοίγει το πρώτο μενού.
  - Μέσα σε μενού: ←/→ αλλάζουν μενού, ↑/↓ αλλάζουν στοιχείο, RETURN/ENTER/SPACE επιλέγουν, ESC κλείνει.
  - Έξω από μενού: TAB/SHIFT+TAB μετακινούν την εστίαση, RETURN/ENTER/SPACE ενεργοποιούν το κουμπί με την εστίαση, CONTROL+γράμμα εκτελεί τη συντόμευση του αντίστοιχου στοιχείου μενού.
- **Ποντίκι:** κλικ σε τίτλο ανοίγει ή κλείνει το μενού. Όσο ένα μενού είναι ανοιχτό, το πέρασμα του pointer αλλάζει μενού και στοιχείο. Κλικ σε στοιχείο το επιλέγει, κλικ έξω κλείνει. Κλικ σε κουμπί του δίνει την εστίαση και το ενεργοποιεί.
- **Cursor keys:** όσο είναι ανοιχτό μενού ή διάλογος, κάνουν πλοήγηση. Αλλιώς κινούν τον pointer.
- **Διάλογοι** (`dialog_run`):
  - modal, κεντραρισμένοι,
  - τίτλος, κείμενο σε πολλές γραμμές με `|` ως αλλαγή γραμμής, 1–3 κουμπιά,
  - ←/→/TAB μετακινούν την εστίαση, RETURN διαλέγει, ESC διαλέγει το τελευταίο κουμπί.
- **Αποθήκευση φόντου:** μενού και διάλογοι κρατούν ό,τι καλύπτουν στη **bank 6** και το επαναφέρουν όταν κλείνουν. Η εφαρμογή δεν χρειάζεται να ξανασχεδιάσει τίποτα.
- **Pointer:** όταν η σχεδίαση πέφτει πάνω του, η `ptr_guard` τον κρύβει αυτόματα, και το `ptr_update` τον ξαναδείχνει στο επόμενο frame. Όταν αλλάζει το mode, το x κλιμακώνεται ώστε ο pointer να μένει στο ίδιο σημείο της οθόνης.
- **Mode 0:** οι τίτλοι παίρνουν μικρότερα περιθώρια, ώστε να χωράνε στις 24 στήλες. Η ένδειξη EN/EL εμφανίζεται μόνο αν υπάρχει χώρος. Όλο το κείμενο κόβεται στη δεξιά άκρη.
- **Δεν υλοποιήθηκαν ακόμα:** απενεργοποιημένα στοιχεία μενού, λίστες, πεδία κειμένου ως widgets, παράθυρα. Έρχονται με το shell (M5).

## 4. Πυρήνας (kernel)

### 4.1 Εκκίνηση

- Φάση 1: φόρτωση από BASIC με `RUN"VOS"` (απλό, συμβατό με κάθε δισκέτα DATA). Η AMSDOS φορτώνει μόνο το `VOS.BIN`. Ο loader κλείνει τις ROM, μεταφέρει τον kernel στο `#0000` και από εκεί και πέρα όλα τα αρχεία (και το `GREEK.LNG`) διαβάζονται με τον δικό μας driver.
- Φάση 2: δισκέτα εκκίνησης τύπου SYSTEM με `|CPM` που φορτώνει boot sector από track 0, ώστε το V-OS να μην εξαρτάται καθόλου από AMSDOS.
- Μετά τη φόρτωση: απενεργοποίηση ROM, εγκατάσταση δικού του interrupt handler (IM 1 στο `&0038`), αρχικοποίηση CRTC, παλέτας, πληκτρολογίου, FDC.

### 4.2 Χάρτης μνήμης

Σήμερα (M22): kernel `#0000–#3DFF` (≈15K χρησιμοποιούνται, τελειώνει στο `#3C0E`· μένουν περίπου 500 bytes, και στη σελίδα μηδέν, μετά τα restart vectors, ο κώδικας των θέσεων προγραμμάτων), stack έως `#4000`, παράθυρο bank `#4000–#7FFF` (bank 4 = buffer αρχείων για στοιχεία, αντιγραφή και φόρτωση όψεων, και όσο τρέχει ένα πρόγραμμα η bank δεδομένων του, bank 5 = η όψη που τρέχει στο `#4000–#4FFF` και από το `#5000` τα προγράμματα με πίνακα relocation, όσα χωράνε (ή ένα χωρίς πίνακα σε όλη τη bank), bank 6 = φόντο κάτω από μενού και διαλόγους ως το `#6FFF` και από το `#7000` το desk accessory (ως 4K), bank 7 = language pack έως 8K, από το `#6000` οι λίστες των πάνελ του Commander, από το `#6800` τα αγγλικά κείμενα, ως 2K, από το `#7000` το kernel extension, ως 4K, με τον πίνακα των προγραμμάτων στο `#7F00`· με επέκταση RAM, οι banks της για προγράμματα), οθόνη και buffers στα κενά της `#8000–#FFFF` (στο `#8000`, που δεν φαίνεται, ο πίνακας 16 bytes του κειμένου, που θέλει αρχή σελίδας· στο `#8800` και στο `#9000`, επίσης κρυφά, buffers του kernel που γράφονται πάντα πριν διαβαστούν· στο `#9800` οι μεταβλητές του συρσίματος και του παρασκηνίου, στο `#A000` η θέση του παραθύρου του Desktop, στο `#A800` οι μεταβλητές του F6· τα `#B000` και `#B800` είναι ελεύθερα· ο loader μηδενίζει όλη τη μνήμη της οθόνης). Ο αρχικός σχεδιασμός:

| Περιοχή | Περιεχόμενο |
|---|---|
| `&0000–&00FF` | Restart vectors, interrupt handler, πίνακας κλήσεων API |
| `&0100–&3FFF` | Kernel: drivers, γραφικά, UI, filesystem (~16K) |
| `&4000–&7FFF` | Παράθυρο bank: εφαρμογή χρήστη ή δεδομένα της (banks `&C4–&C7`, 4×16K) |
| `&8000–&FFFF` | Οθόνη overscan 32K (26K χρήσιμα + buffers στα κενά) |

Το βασικό ζήτημα είναι ότι η οθόνη των 32K αφήνει μόνο 32K στη βασική μνήμη. Εναλλακτικές:
- εφαρμογές μέχρι 16K ανά bank, με κλήσεις kernel από το παράθυρο `&4000`,
- μέρος του kernel (π.χ. filesystem, γραμματοσειρές) σε bank που εναλλάσσεται όταν χρειάζεται,
- χρήση των configurations `&C1`/`&C2`/`&C3` για μεγαλύτερες εφαρμογές.

### 4.3 Υπηρεσίες

- **Βρόχος συμβάντων**: ουρά (πλήκτρα, ποντίκι, timer, δίσκος, μηνύματα), dispatch στην ενεργή εφαρμογή.
- **Χρονόμετρα**: μετρητής frames (50 Hz) και ticks (300 Hz), ρολόι ώρας λογισμικού, `wait`.
- **Διαχείριση μνήμης**: δέσμευση/απελευθέρωση banks και μπλοκ μέσα σε αυτά, σωρός για το UI.
- **Loader**: φόρτωση εφαρμογής από δισκέτα, έλεγχος header, relocation, κλήση των σημείων εισόδου.
- **Πολυεργασία**: συνεργατική (cooperative). Μία εφαρμογή τη φορά συν μικρά «desk accessories» (ρολόι, σημειώσεις) που τρέχουν στο ίδιο event loop. Όχι preemptive. *Υλοποίηση M14:* ένα accessory τη φορά, με relocation στη bank 6, F5 (§7.3).
- **Χειρισμός σφαλμάτων**: παράθυρο σφάλματος συστήματος, επιστροφή στο shell χωρίς επανεκκίνηση όπου είναι εφικτό.
- **Ήχος**: απλός driver AY (beep, νότα, ένταση, σίγαση) που τρέχει στο interrupt.

## 5. Driver δισκέτας και σύστημα αρχείων

### 5.1 Χαμηλό επίπεδο (FDC µPD765)

- Θύρες: `&FB7E` (status), `&FB7F` (data), `&FA7E` (motor on/off).
- Εντολές: Specify, Recalibrate, Seek, Sense Interrupt Status, Read ID, Read Data, Write Data, Format Track, Sense Drive Status.
- Μεταφορά δεδομένων με polling του status register. Ο βρόχος πρέπει να είναι αρκετά γρήγορος ώστε να μη χάνεται byte (overrun). Κατά τη μεταφορά τα interrupts απενεργοποιούνται ή ο handler συντομεύει.
- Διαχείριση μοτέρ: εκκίνηση με αναμονή ~1 s, αυτόματο σβήσιμο μετά από αδράνεια.
- Επαναλήψεις και αναφορά σφαλμάτων (no ID, CRC, write protect, not ready) σε κατανοητά μηνύματα.
- Δύο μονάδες (A:, B:), 40 tracks στα 3", προαιρετικά 80 tracks για εξωτερικό 3,5".

**Υλοποίηση M4** (`src/drivers/fdc.asm`): Specify, Recalibrate, Seek, Sense Interrupt Status, Read ID, Read Data, Write Data, ένας sector τη φορά. Ο CPC δεν έχει γραμμή TC, οπότε κάθε εντολή δίνει τον ίδιο sector ως R και EOT και η σημαία «end of cylinder» αγνοείται. Τα interrupts κλείνουν μόνο όσο διαρκεί η μεταφορά ενός sector. Κάθε αναμονή (byte εντολής, εκτέλεση, αποτέλεσμα, seek) έχει όριο· το timeout σταματά την εντολή και επιστρέφει «δεν είναι έτοιμη». Το αποτέλεσμα διαβάζεται όσο ο FDC είναι απασχολημένος (bit CB), γιατί κάποιοι emulators δίνουν λιγότερα από 7 bytes. Τρεις προσπάθειες· πριν από κάθε νέα ο ελεγκτής αδειάζει, ξαναπαίρνει SPECIFY και κάνει recalibrate. Οι κανόνες αυτοί προέρχονται από τον driver του TerraCPC, που δουλεύει σε πραγματικό CPC. Το μοτέρ ανάβει με αναμονή 1 s και σβήνει μετά από 3 s αδράνειας (`fdc_tick`). Στο M5 προστέθηκαν η μονάδα B: (`fdc_select`) και το Format Track (`fdc_format`, 9 sectors με το interleave της AMSDOS: C1 C6 C2 C7 C3 C8 C4 C9 C5). Μένουν: Sense Drive Status, 80 tracks.

### 5.2 Μορφή δισκέτας

**Απόφαση:** συμβατότητα με τη μορφή **AMSDOS DATA** (40 tracks, 9 sectors × 512 bytes, IDs `&C1–&C9`, 178K, 64 εγγραφές καταλόγου, blocks 1K, κατάλογος τύπου CP/M 2.2).

Πλεονεκτήματα: τα αρχεία του V-OS διαβάζονται από BASIC, emulators και εργαλεία (`iDSK`, RASM), και αντίστροφα. Το V-OS χρησιμοποιεί το header των 128 bytes του AMSDOS για να σημειώνει τον τύπο του αρχείου.

Το V-OS αναγνωρίζει τη μορφή από το ID του πρώτου sector (Read ID): DATA (`#C1–#C9`, 180 blocks) ή SYSTEM (`#41–#49`, 2 δεσμευμένα tracks, 171 blocks).

Ένα δικό του filesystem (μεγαλύτερα ονόματα, φάκελοι) δεν είναι στόχος. Αν χρειαστεί ποτέ, θα είναι δεύτερη μορφή δίπλα στην AMSDOS.

### 5.3 Υψηλό επίπεδο

- Κατάλογος (catalog), open/read/write/close, διαγραφή, μετονομασία, ελεύθερος χώρος, format, αντιγραφή δισκέτας.
- Buffer ενός sector ή ενός track (4,5K) για ταχύτητα.
- **Υλοποίηση M4** (`src/kernel/fs.asm`): `fs_catalog` (λίστα αρχείων με μέγεθος), `fs_load` (σε οποιαδήποτε bank, έως 16K, με ή χωρίς header), `fs_save` (header AMSDOS με checksum, αντικαθιστά παλιό αρχείο με το ίδιο όνομα), `fs_delete`, `fs_free_k`. Κάθε κλήση ξαναδιαβάζει τον κατάλογο, ώστε να φαίνεται η αλλαγή δισκέτας. Το παράθυρο επιλογής αρχείου είναι στο `src/ui/filedlg.asm`. Στο M5b προστέθηκαν `fs_rename` και `fs_copy` (αντιγραφή sector προς sector ανά 16K μέσω της bank 4, χωρίς όριο μεγέθους). Στο M5c προστέθηκαν `fs_format` (DATA), `fs_exists` και επιβεβαίωση αντικατάστασης στην αντιγραφή. Μένει: άνοιγμα/ανάγνωση ροής για φόρτωση αρχείων πάνω από 16K.
- Τύποι αρχείων V-OS: `.BIN` (εφαρμογή), `.VBP` (project blocks), `.SCR` (εικόνα), `.SND`, `.FNT`, `.DRV`, `.CFG`.

### 5.4 Αλληλεπίδραση με την οθόνη

Αν ενεργοποιηθεί η μικτή οθόνη (πρότυπο D), οι προσβάσεις στη δισκέτα με κλειστά interrupts σπάνε το raster split. Κατά την ανάγνωση και εγγραφή η οθόνη επιστρέφει προσωρινά σε ενιαίο mode ή ο driver σχεδιάζεται να κάνει τη μεταφορά ανάμεσα στα interrupts.

## 6. Περιβάλλον χρήστη (shell)

**Απόφαση:** ένα shell με τρεις όψεις. Το Desktop (A) είναι η αρχική οθόνη, ο Launcher (B) και ο Commander (C) είναι εναλλακτικές όψεις.

### 6.1 Οι τρεις όψεις

| Όψη | Mode | Ρόλος | Πώς ανοίγει |
|---|---|---|---|
| A · Desktop | 1 | Αρχική οθόνη: γραμμή μενού, παράθυρα, εικονίδια δίσκων, εφαρμογές σε παράθυρα | Προεπιλογή εκκίνησης, `1`, μενού Launcher → Desktop, Commander → Options |
| B · Launcher | 0 | Πλέγμα 3×3 πλακιδίων για γρήγορη εκκίνηση, φιλικό σε παιδιά και joystick | `2`, μενού View (A) ή Options (C) |
| C · Commander | 1 | Δύο πάνελ A:/B:, αντιγραφή, format, μαζικές ενέργειες σε αρχεία | `3`, μενού View (A) ή Sys (B) |

Στο πραγματικό μηχάνημα οι συντομεύσεις `1/2/3` μπορούν να είναι τα πλήκτρα f1/f2/f3 του αριθμητικού πληκτρολογίου, ώστε να μη συγκρούονται με την πληκτρολόγηση.

**Υλοποίηση M5a** (`src/shell/commander.asm`): ο Commander είναι η πρώτη όψη και, προς το παρόν, η αρχική οθόνη. Δύο πάνελ (A: αριστερά, B: δεξιά), 20 γραμμές το καθένα, με τίτλο «μονάδα, μορφή, πλήθος αρχείων» και ελεύθερο χώρο. Ενέργειες: στοιχεία αρχείου, αντιγραφή στο απέναντι πάνελ (έως 16K, με ή χωρίς header), διαγραφή, ξαναδιάβασμα. Οι λίστες κρατιούνται στη bank 5 (`#4000` για το A:, `#4400` για το B:). Με τον Commander ανοιχτό τα cursor keys επιλέγουν αρχεία και δεν κινούν τον δείκτη· το AMX Mouse λειτουργεί κανονικά.

### 6.2 Τι μοιράζονται

- **Μηχανή μενού και εστίασης** (§3.3): κάθε όψη δηλώνει μόνο τα μενού και τα στοιχεία της. Η πλοήγηση, το ποντίκι και οι συντομεύσεις είναι κοινός κώδικας.
- **Κατάλογος εφαρμογών**: όνομα, τύπος, εικονίδιο σε δύο εκδοχές (mode 1 για το A, mode 0 για το B), θέση στη δισκέτα. Το C δείχνει τα ίδια αρχεία ως λίστα.
- **Κατάσταση συστήματος**: επιλεγμένη μονάδα, επιλεγμένο αρχείο, πρόχειρο αντιγραφής. Η εναλλαγή όψης κρατά την επιλογή.
- **Ρυθμίσεις**: ποια όψη ανοίγει στην εκκίνηση (π.χ. B για παιδικό προφίλ), αποθηκευμένη στο `SETUP.CFG`.

### 6.3 Εναλλαγή όψης

1. Κλείσιμο ανοιχτού μενού, αποθήκευση της κατάστασης της τρέχουσας όψης.
2. Αναμονή για VSYNC, αλλαγή mode και παλέτας από τον Gate Array, καθάρισμα οθόνης.
3. Πλήρης σχεδίαση της νέας όψης και επαναφορά του δείκτη στη μορφή του νέου mode.

Κάθε όψη έχει δική της παλέτα 4 ή 16 inks. Για συνέπεια, το A και το C μοιράζονται βασικά χρώματα (μπλε φόντο, λευκό κείμενο) και διαφέρουν μόνο στα χρώματα έμφασης.

### 6.4 Μνήμη

Οι τρεις όψεις δεν χωρούν μαζί στα ~16K του kernel. Η πρόταση είναι κάθε όψη να είναι **overlay** σε δική της bank των 16K (ή να φορτώνεται από τη δισκέτα), και ο kernel να κρατά μόνο τον κοινό κώδικα: μενού, εστίαση, γραφικά, αρχεία. Ο Launcher χρειάζεται επιπλέον τις ρουτίνες κειμένου και blit για mode 0.

**Υλοποίηση M5b** (`src/kernel/view.asm`): κάθε όψη είναι αρχείο στο A: (`DESKTOP.OVL`, `LAUNCHER.OVL`, `COMMANDR.OVL`), μεταγλωττισμένο για το `#4000` στην ίδια εκτέλεση της RASM (`BANK`), ώστε να βλέπει τις ετικέτες του kernel. Τρέχει στη bank 5. Ξεκινά με `jp init`, `jp event`, `jp redraw`, `"VV"` και τον αριθμό της. Ο kernel τη φορτώνει πρώτα στη bank 4, ελέγχει το `"VV"` και μετά την αντιγράφει στη bank 5. Κανόνας: κάθε ρουτίνα του kernel που αλλάζει bank επιστρέφει στη bank της όψης (`ram_home`), και οι όψεις δεν αλλάζουν ποτέ bank μόνες τους (`bank_put`, `bank_get`). Οι εντολές αρχείων, τα μενού ΠΡΟΒΟΛΗ και ΒΟΗΘΕΙΑ και η έξοδος είναι κοινός κώδικας στον kernel. Η εναλλαγή όψης δεν κρατά ακόμα την επιλογή αρχείου.

### 6.5 Λοιπά

- Διαχείριση αρχείων: περιήγηση A:/B:, εκτέλεση, αντιγραφή, διαγραφή, μετονομασία, πληροφορίες (στο A ως παράθυρα, στο C ως πάνελ).
- Ρυθμίσεις (Setup): ποντίκι, ταχύτητα επανάληψης πλήκτρων, χρώματα, προτιμώμενο mode, γλώσσα, αποθήκευση σε `SETUP.CFG`. *Υλοποίηση M5c:* όψη Setup (F4, `src/shell/setup.asm`) με όψη εκκίνησης, γλώσσα, επανάληψη πλήκτρων, AMX (ναι/όχι, παλμοί/στάθμες) και χρώμα φόντου σε mode 1. Το `SETUP.CFG` είναι `"VCFG"`, έκδοση 1 και 7 bytes. Χωρίς αυτό η γλώσσα είναι τα Αγγλικά. Η εντολή ΠΡΟΒΟΛΗ > ΓΛΩΣΣΑ αλλάζει και τη ρύθμιση, ώστε να την αποθηκεύει το Setup.
- Διάλογοι συστήματος: μήνυμα, επιβεβαίωση, επιλογή αρχείου, εισαγωγή κειμένου.

### 6.6 Γλώσσες ως plugins (language packs)

**Απόφαση:** υποστήριξη γλωσσών μέσω plugin. Τα Αγγλικά είναι η βασική γλώσσα και πάντα διαθέσιμα: η γραμματοσειρά ASCII και το πληκτρολόγιο είναι στον kernel, τα κείμενα στο `ENGLISH.MSG` (από το M6b, για να χωρά ο kernel). Πρώτο pack: **Ελληνικά**, με εμφάνιση και πληκτρολόγηση. Υλοποιήθηκε στο M2b.

**Πηγές** (κείμενο, UTF-8, στο `lang/`):

| Αρχείο | Περιεχόμενο |
|---|---|
| `lang/en/keymap.txt` | πλήρης αγγλικός χάρτης: `key <αριθμός> <κανονικό> <SHIFT>` |
| `lang/en/messages.txt` | **κύρια λίστα** μηνυμάτων UI: `<ID> <κείμενο>`. Η σειρά ορίζει τους αριθμούς `MSG_<ID>` |
| `lang/<xx>/pack.txt` | κωδικός (`EL`), όνομα, κωδικοσελίδα (`iso8859_7`) |
| `lang/<xx>/font.txt` | glyphs 8×8 για τους κωδικούς 128–255 (`#` = μελάνι) |
| `lang/<xx>/keymap.txt` | μόνο τα πλήκτρα που αλλάζουν, `dead:<όνομα>` για dead keys, `combo <dead> <βάση> <αποτέλεσμα>` |
| `lang/<xx>/messages.txt` | μεταφράσεις οποιουδήποτε υποσυνόλου των ID |

Το `tools/mklng.py kernel` παράγει τα `src/lang/msg_ids.inc`, `src/lang/lang_en.asm` (πίνακες πληκτρολογίου του kernel) και το `ENGLISH.MSG` (`"VMSG"`, έκδοση 1, και πίνακας μηνυμάτων όπως στα `.LNG`). Ο kernel το φορτώνει στη bank 7 στο `#6800` και από εκεί παίρνει κάθε κείμενο που λείπει από το pack. Αν λείπει και το ίδιο, τα κείμενα εμφανίζονται ως `?`. Το `tools/mklng.py pack` παράγει το `.LNG`. Νέα γλώσσα σημαίνει νέο φάκελο στο `lang/`, χωρίς αλλαγές στον kernel.

**Μορφή `.LNG`** (περιγράφεται αναλυτικά στο `tools/mklng.py`):

| Μέρος | Περιεχόμενο | Μέγεθος |
|---|---|---|
| Header | `VLNG`, έκδοση 1, κωδικός, offsets, μέγεθος, όνομα (12 bytes) | 32 bytes |
| Γραμματοσειρά | 128 glyphs για τους κωδικούς 128–255 | 1024 bytes |
| Πίνακας κεφαλαίων/πεζών | ανά κωδικό: σημαία γράμματος και ο κωδικός του άλλου case | 256 bytes |
| Keymap | 80 κανονικά + 80 με SHIFT. Οι κωδικοί 1–7 είναι dead keys | 160 bytes |
| Συνδυασμοί | (dead, βάση, αποτέλεσμα) …, 0 | 3 bytes ανά συνδυασμό |
| Μηνύματα | πλήθος, offsets (0 = αμετάφραστο), κείμενα | ανάλογα |

Το ελληνικό pack είναι 2.483 bytes. Το όριο είναι 16.384 bytes (μία bank).

**Στον kernel** (`src/kernel/lang.asm`):
- **Φόρτωση:** από το M4 το `lang_init` διαβάζει το `GREEK.LNG` κατευθείαν στη bank 7 με τον δικό μας driver (`fs_load`). Αν το αρχείο λείπει ή η δισκέτα δεν διαβάζεται, το σύστημα μένει στα Αγγλικά. Από το M22 το όνομα του pack έρχεται από το `SETUP.CFG` (`CFG_PACK`).
- **Μνήμη:** το `lang_init` (από το M17 στο kernel extension της bank 7, `src/kernel/ext.asm`) κρατά στα κενά της μνήμης οθόνης τη γραμματοσειρά, τον πίνακα κεφαλαίων/πεζών, το keymap και τους συνδυασμούς (~1,6K), επειδή τα χρειάζονται το κείμενο και το interrupt του πληκτρολογίου. Ολόκληρο το pack πάει στη **bank 7**.
- **Κείμενα UI:** ο kernel και οι εφαρμογές δεν γράφουν κείμενα απευθείας. Το `lang_msg` (A = `MSG_*`) επιστρέφει το κείμενο στη γλώσσα του UI. Το αντιγράφει από τη bank 7, ή δίνει το αγγλικό αν λείπει η μετάφραση.
- **Κείμενο οθόνης:** το `txt_char` σχεδιάζει τους κωδικούς 32–127 με τη γραμματοσειρά του kernel και τους 128–255 με τη γραμματοσειρά του pack.
- **Δύο ανεξάρτητες γλώσσες:** η γλώσσα του UI (`lang_ui`) και η γλώσσα πληκτρολόγησης (`lang_input`).
  - **CONTROL+SHIFT**, με οποιαδήποτε σειρά, αλλάζει την πληκτρολόγηση EN ↔ pack και στέλνει το συμβάν `EV_LANG`.
  - Η ένδειξη EN/EL φαίνεται στη γραμμή τίτλου.
  - Στο pack, το CAPS LOCK αλλάζει κεφαλαία/πεζά μέσω του πίνακα κεφαλαίων/πεζών.
- **Dead keys:** δεν δίνουν χαρακτήρα. Ο επόμενος χαρακτήρας συνδυάζεται με το dead key, αν υπάρχει τέτοιος συνδυασμός. Αλλιώς γράφεται κανονικά.
- **Ονόματα αρχείων:** μένουν ASCII για συμβατότητα με την AMSDOS. Τα ελληνικά επιτρέπονται στο περιεχόμενο των αρχείων και στο UI.

**Ελληνικό pack:**
- **Κωδικοσελίδα:** ISO 8859-7. Τα αρχεία κειμένου μετατρέπονται εύκολα σε PC.
- **Γραμματοσειρά:** font8x8 (public domain). Τα κεφαλαία με τόνο, τα ϊ ϋ ό ύ ώ και τα ΄ ΅ · συντέθηκαν από το `tools/fonts/make_greek_font.py`. Διορθώνονται με το χέρι στο `lang/el/font.txt`.
- **Πληκτρολόγιο:** ελληνική διάταξη του PC.
  - `;` = dead key τόνου, SHIFT+`;` = dead key διαλυτικών.
  - Το Q δίνει το ελληνικό ερωτηματικό `;`, το W το `ς`.
  - Τόνος ή διαλυτικά ακολουθούμενα από κενό δίνουν το σκέτο σημάδι.
- **Δοκιμή:** στον Caprice32 (`make test-input`), πληκτρολογήθηκε «καλημέρα Γεια Ά» σε mode 1 και mode 0.

## 7. API για εφαρμογές

### 7.1 Μηχανισμός κλήσης

- Σταθερός πίνακας άλματος (jump table) σε γνωστή διεύθυνση, π.χ. `CALL &0103 + 3*n`, ή `RST &28` ακολουθούμενο από έναν byte αριθμό συνάρτησης (μικρότερος κώδικας, λίγο πιο αργό).
- Συμβάσεις καταχωρητών: παράμετροι σε `A, BC, DE, HL`, επιστροφή σε `A`/`HL`, σφάλμα στο Carry flag. Τεκμηριωμένο ποιοι καταχωρητές καταστρέφονται.
- Αριθμός έκδοσης API, ώστε οι εφαρμογές να ελέγχουν τη συμβατότητα.

### 7.2 Ομάδες συναρτήσεων (ενδεικτικά)

| Ομάδα | Συναρτήσεις |
|---|---|
| `SYS` | version, exit, yield, get_ticks, wait_frames, random |
| `MEM` | alloc_bank, free_bank, alloc, free |
| `GFX` | set_mode, set_ink, cls, plot, line, rect, fill_rect, blit, sprite_draw, sprite_erase, set_clip |
| `TXT` | print_at, print_char, set_font, text_width |
| `LANG` | msg (κείμενο UI ανά `MSG_*`), toggle_input, other_case, combine, code (υπάρχουν στον kernel από το M2b) |
| `UI` | set_bar, draw_bar, set_widgets, draw_widgets, event (→ εντολή), dialog_run (υπάρχουν από το M3); dialog_file, list, window (M5) |
| `INP` | key_pressed, key_get, mouse_get, joy_get, wait_event |
| `FILE` | catalog, open, read, write, close, delete, rename, free_space |
| `SND` | beep, note, volume, silence |

**Υλοποίηση M6** (`src/api/vos_api.inc`, `src/kernel/api.asm`): πίνακας άλματος `CALL VOS_xxx` στο `#0108` (μετά από `"VOS",0`, έκδοση kernel και έκδοση API στο `#0100`), 31 κλήσεις, έκδοση API 1. Παράμετροι σε `A, BC, DE, HL` (και `IX` για ορθογώνιο), σφάλμα στο Carry. Τα προγράμματα δεν περιμένουν είσοδο: ο kernel καλεί το `event` τους για κάθε συμβάν (και ανά frame με `VOS_TICKS`). Τα κείμενα `#C0`+ είναι του προγράμματος (`VOS_TEXTS`), σε δύο γλώσσες.

**Υλοποίηση M9 (bank δεδομένων):**
- **Ποια bank:** το CPC 6128 έχει μόνο τις banks 4–7, και ο kernel τις χρησιμοποιεί όλες. Η bank 4 όμως χρειάζεται μόνο στις όψεις (στοιχεία, αντιγραφή, `SETUP.CFG`) και όταν φορτώνεται η επόμενη όψη ή το επόμενο πρόγραμμα. Όσο τρέχει ένα πρόγραμμα είναι δική του: 16K ακόμα.
- **Πώς τη βλέπει το πρόγραμμα:** στις ίδιες διευθύνσεις `#4000–#7FFF`, αλλά δεν τη βάζει ποτέ στη θέση του εαυτού του. Αντιγράφει από και προς αυτή:
  - `VOS_BANK_GET` (HL = πηγή στη bank, DE = προορισμός, BC = bytes) και `VOS_BANK_PUT` (ανάποδα). Ο kernel περνά τα δεδομένα από το `fs_buf`, 512 bytes τη φορά.
  - `VOS_LOAD` και `VOS_SAVE` με μονάδα + `VOS_DATA` (`#80`) φορτώνουν και αποθηκεύουν αρχεία κατευθείαν στη bank.
- **Περιορισμοί:**
  - Στην αρχή η bank έχει ένα αντίγραφο του αρχείου του προγράμματος. Κρατά ό,τι γράψει το πρόγραμμα ως το τέλος του.
  - Οι κλήσεις γίνονται από τη στοίβα του kernel (`init`, `event`), όχι από στοίβα μέσα στο `#4000–#7FFF`, όπως οι στοίβες των scripts του runtime.
- **API έκδοση 6** (39 κλήσεις). Ο kernel μεγάλωσε κατά 120 bytes.
- **Πρώτος χρήστης, το Studio:**
  - Στο `init` αντιγράφει τον παίκτη (3,7K) στη bank. Ο χώρος του στη μνήμη του Studio γίνεται ο buffer του `.VBS`, οπότε το Studio πιάνει 11,3K αντί για 14,6K.
  - Η ΕΚΤΕΛΕΣΗ βάζει το πρόγραμμα αμέσως μετά τον παίκτη στη bank και αποθηκεύει το `.BIN` από εκεί, με σωστή διεύθυνση φόρτωσης `#4000`.
  - Το ΑΝΟΙΓΜΑ φορτώνει το `.VBS` στη bank και το ελέγχει εκεί. Ένα αρχείο που δεν είναι πρόγραμμα δεν αλλάζει πια αυτό που είναι ανοιχτό.
- **Δεν έγινε:** προγράμματα με κώδικα πάνω από 16K. Θα ήθελαν relocation ή overlays. Με αυτές τις κλήσεις ένα πρόγραμμα μπορεί να κρατά δεδομένα και εικόνες έξω από τη μνήμη του.

### 7.3 Μορφή εφαρμογής (`.BIN` του V-OS)

Header με:
- magic `VOS`, έκδοση API, ζητούμενο mode (0, 1, μικτό),
- μέγεθος κώδικα και δεδομένων, πίνακα relocation,
- σημεία εισόδου: `init`, `event`, `draw`, `exit`,
- όνομα (έως 8 χαρακτήρες) και εικονίδιο 16×16 για το shell.

**Υλοποίηση M6:** binary με header AMSDOS για το `#4000`, έως 16K σε μία bank (5). Στην αρχή του: `jp init`, `jp event`, `jp redraw`, `"VA"`, έκδοση API. Το όνομα είναι του αρχείου. Δεν υπάρχει επιλογή mode στο header: το πρόγραμμα ορίζει μόνο του mode και παλέτα στο `init`. Το relocation ήρθε στο M14 (παρακάτω).

**Υλοποίηση M14 (relocation και desk accessory):**
- **Πίνακας relocation:** στο τέλος του αρχείου, μετά τα bytes του προγράμματος: `dw` οι θέσεις των high bytes των διευθύνσεων του ίδιου του προγράμματος, `dw` το πλήθος τους, `"RL"`.
  - Το `tools/mkreloc.py` τον φτιάχνει από δύο μεταγλωττίσεις, στο `#4000` και στο `#4100` (`-DVOS_RELOC_PASS=1`). Τα bytes που διαφέρουν κατά 1 είναι οι θέσεις· οποιαδήποτε άλλη διαφορά είναι σφάλμα.
  - Η μετακίνηση γίνεται κατά ολόκληρες σελίδες, οπότε αλλάζουν μόνο αυτά τα bytes.
  - Ως κανονικό πρόγραμμα στο `#4000` ο πίνακας αγνοείται, οπότε τα αρχεία με πίνακα τρέχουν και σε παλιό kernel.
- **Desk accessory:** ένα πρόγραμμα ως `ACC_MAX` (4K) με πίνακα relocation.
  - Ο Launcher (ΑΡΧΕΙΟ > ΩΣ ΑΞΕΣΟΥΑΡ, ^A) το φορτώνει στη bank 4, το μεταφέρει στο `ACC_ADDR` (`#7000`) με το `reloc` του kernel και το αντιγράφει στη bank 6 (`bank_copy`). Μετά το ανοίγει.
  - Το F5 το ανοίγει και το κλείνει πάνω από οποιαδήποτε όψη ή πρόγραμμα, έξω από μενού.
  - **Όσο είναι ανοιχτό:** είναι η bank «σπίτι» (`ram_home_cfg`) και το `cur_base`, οπότε ο kernel του στέλνει όλα τα γεγονότα (`cur_call`). Το πρόγραμμα δεν παίρνει κανένα.
  - **Δική του κατάσταση:** τα `view_ticks`, `app_texts`, `ui_widgets` και `ui_bar` (7 bytes, `acc_swap`). Δεν έχει γραμμή μενού.
  - **Κλείσιμο:** στο κλείσιμο (F5, ή `VOS_EXIT` από το ίδιο) το πρόγραμμα ξανασχεδιάζει τα πάντα (`redraw`). Το άνοιγμα και το κλείσιμο γίνονται στον βρόχο του kernel (`acc_req`, `view_poll`), όχι μέσα σε event, γιατί αλλάζουν τη bank του κώδικα που τρέχει.
  - **`init`:** παίρνει A = 1 ως accessory και A = 0 ως πρόγραμμα. Ως accessory σχεδιάζει μόνο ένα παράθυρο, στο mode που είναι επιλεγμένο, χωρίς mode, παλέτα ή μενού. Δεν χρησιμοποιεί τη bank δεδομένων, που είναι του προγράμματος.
  - **Αλλαγή όψης ή προγράμματος:** το accessory κλείνει (`acc_reset`).
- **Φόντο διαλόγων:** το `ui_copy_area` σταματά στο `ACC_ADDR`, οπότε ένας τεράστιος διάλογος δεν πατά το accessory. Οι γραμμές μετά δεν κρατιούνται.
- **API έκδοση 7:** το `VOS_FRAMES` δίνει και A = bits 16..23. Ο μετρητής είναι 24 bits, σχεδόν 4 ημέρες, για ρολόι.
- **Παράδειγμα:** το `apps/clock/clock.asm`, ΡΟΛΟΙ με τον χρόνο από την εκκίνηση. Ως πρόγραμμα σε mode 1 με μενού, ως accessory σε παράθυρο 96×34.
- **Kernel:**
  - Ο kernel μεγάλωσε κατά 236 bytes. Ο έλεγχος του αρχείου είναι στον Launcher (overlay), και στον kernel μένει μόνο ο βρόχος του relocation, που θέλει τη bank 4 στη θέση της.
  - Οι δοκιμαστικές εκδόσεις χωράνε ακόμα στο `+#100`. Τα κενά της σελίδας `#8000` είναι μόνο τα `#x000–#x01F`, δεν υπάρχει άλλος χώρος εκεί.
- **Διορθώσεις στον Launcher:** με περισσότερα από 9 προγράμματα, η αλλαγή σελίδας με τα βελάκια σχεδίαζε δύο πλακίδια σε λάθος θέσεις. Το `ln_select` διάβαζε την παλιά επιλογή από τον B μετά το `ln_remember`, που τον μηδενίζει.

**Υλοποίηση M15 (relocation σε όλα τα προγράμματα, πρώτο βήμα για πολλά προγράμματα μαζί):**
- **Ποια προγράμματα:** DEMO, MIXED, CLOCK και όσα βγάζει το `vbc.py` (PONG, CATCH, STARCAT, COUNTER) έχουν πίνακα relocation. Ο πίνακας μεγαλώνει το αρχείο κατά 10–15%.
  - Το Makefile έχει έναν κοινό κανόνα (`reloc_app`) για τα προγράμματα σε assembly. Το `vbc.py` μεταγλωττίζει δύο φορές και καλεί το `mkreloc.relocate`.
  - Το STUDIO, το VBRUN και ό,τι τρέχει αυτό (CALC, FLAP και τα προγράμματα που γράφει το Studio) δεν έχουν πίνακα: ο παίκτης κρατά δεδομένα σε σταθερές διευθύνσεις (`#7500–#7FFF`) και χρειάζεται ολόκληρη τη bank. Μένουν στο `#4000`.
- **Kernel:** το `app_run` βρίσκει τον πίνακα (`reloc_find`, που μεταφέρθηκε από τον Launcher), αφήνει έξω τα bytes του και, αν το `app_moved` δεν είναι 0, μετακινεί το πρόγραμμα (`reloc`, με τον αριθμό σελίδων). Το `view_install` το αντιγράφει στη σελίδα `vw_page` με το `bank_copy`, ακριβώς όσα bytes έχει, και το `cur_base` δείχνει εκεί. Οι όψεις μένουν στο `#4000`.
  - Στην κανονική έκδοση το `app_moved` ήταν 0, οπότε η συμπεριφορά δεν άλλαζε. Στο M16 τη θέση τη δίνει ο πίνακας προγραμμάτων.
  - Η αντιγραφή με `bank_copy` είναι μικρότερη από τον παλιό βρόχο. Παρ' όλα αυτά οι δοκιμαστικές εκδόσεις ξεπέρασαν το `+#100` κατά 23 bytes.
  - Γι' αυτό τρεις buffers που γράφονται πάντα πριν διαβαστούν πήγαν στα κρυφά κενά 32 bytes της σελίδας `#8000`: τα `app_self` και `app_parent` και το `acc_ctx` στο `#8800`, το `bank_buf` στο `#9000`. Ο kernel τελειώνει πλέον στο `#3D59`, πιο νωρίς από το M14 (`#3D68`).
- **Δοκιμή:** το `make test-reloc` χτίζει με `-DTEST_RELOC=35`, οπότε τα προγράμματα με πίνακα φορτώνονται στο `#6300`. Τα DEMO, PONG και MIXED τρέχουν σωστά από εκεί και ο Launcher γυρίζει μετά από το καθένα. Στο M16 τη θέση του πήρε το `make test-multi`, αφού όλα τα προγράμματα με πίνακα τρέχουν πλέον από το `#5000` και πάνω.
- **Λάθη που βρέθηκαν:** η RASM διαβάζει το `-DTEST_RELOC=#23` ως 0 (θέλει δεκαδικό). Ένα `scf` στο `reloc_find` άφηνε το carry στο επόμενο `sbc` και ο πίνακας διαβαζόταν ένα byte πιο πριν.

**Υλοποίηση M16 (πολλά προγράμματα μαζί):**
- **Μνήμη (bank 5):** η όψη (Desktop, Launcher, Commander, Setup, η καθεμιά ως 1,5K) στο `#4000–#4FFF` (`PROG_ADDR`). Από το `#5000` ως το `#7FFF` (12K) τα προγράμματα με πίνακα relocation, το καθένα όπου βρεθεί χώρος, ως τέσσερα.
  - **Θέσεις:** τέσσερις, στα κρυφά κενά 32 bytes `#9800`, `#A000`, `#A800`, `#B000`. Η καθεμιά κρατά πρώτη σελίδα (0: ελεύθερη), σελίδες, μονάδα και όνομα. Ο loader μηδενίζει όλη τη μνήμη της οθόνης, οπότε ξεκινούν άδειες χωρίς κώδικα στον kernel.
  - **Χώρος:** το `slot_alloc` ψάχνει την πρώτη σελίδα από το `#50` όπου χωρά το πρόγραμμα χωρίς να πέφτει σε άλλο. Το `app_slot` είναι η θέση του προγράμματος που τρέχει (0: ένα χωρίς πίνακα, σε όλη τη bank). Το `api_end` (VOS_EXIT, VOS_RUN) την ελευθερώνει.
  - **Χωρίς πίνακα** (STUDIO, CALC, FLAP): τρέχει μόνο αν δεν υπάρχει άλλο πρόγραμμα. Αλλιώς βγαίνει το σφάλμα 13, «CLOSE ANOTHER|PROGRAM FIRST», σε δύο γραμμές, γιατί σε mode 0 ο διάλογος χωρά ως 20 χαρακτήρες. Μια όψη το τερματίζει όπως πριν.
- **Εναλλαγή:** τα F1–F4 πηγαίνουν σε όψη χωρίς να τερματίζουν το πρόγραμμα, που απλώς δεν παίρνει πια γεγονότα. Στον Launcher, το RUN σε πρόγραμμα που τρέχει ήδη (`ln_slot`, στον ίδιο δίσκο A:) γράφει τη θέση του στο `app_wake`. Το `app_run` τότε δεν φορτώνει τίποτα· ξεκινά το πρόγραμμα από τη θέση του με A = 2 (`view_start`). Το Desktop και ο Commander φορτώνουν πάντα νέο αντίγραφο.
- **API 8, `init` με A = 2:** το πρόγραμμα ξαναθέτει mode, παλέτα, μενού, κουμπιά και `VOS_TICKS` και ξανασχεδιάζει, κρατώντας την κατάστασή του. Το DEMO και το MIXED το κάνουν ήδη. Το runtime των blocks δεν ξαναξεκινά τα scripts· με `RT_ALONE` (ο παίκτης, που δεν συνεχίζει ποτέ) ο κώδικας αυτός λείπει, γιατί το Studio είχε 6 bytes ελεύθερα. Το ΡΟΛΟΙ κρατά μόνο το bit 0 (accessory). Ένα παλιό πρόγραμμα που αγνοεί το A ξεκινά απλώς από την αρχή.
- **Launcher:** κρατά τα εικονίδια μόνο της σελίδας που δείχνει (9 × 256 bytes, `ln_owner`), ώστε να χωρά κάτω από το `#5000`· σε αλλαγή σελίδας τα διαβάζει ξανά. Όλες οι όψεις ελέγχονται στη μετάφραση να τελειώνουν ως το `PROG_ADDR`.
- **Kernel:** οι ρουτίνες relocation και θέσεων (`kernel/slots.asm`, ≈150 bytes) μπήκαν στη σελίδα μηδέν, στα κενά ανάμεσα στα restart vectors και στον πίνακα του API. Ο kernel τελειώνει στο `#3D77`, η μεγαλύτερη δοκιμαστική έκδοση στο `#3EF6`.
- **Όρια:** τα προγράμματα στο παρασκήνιο είναι παγωμένα (κανένα γεγονός). Στη συνέχιση, όσα έχει τυπώσει ένα πρόγραμμα του `vbc` με PRINT χάνονται ως την επόμενη αλλαγή τους (στο PONG το σκορ), όπως και στην αλλαγή γλώσσας. Δεν υπάρχει ακόμα σημάδι στα πλακίδια των προγραμμάτων που τρέχουν. Ο διάλογος σφάλματος έχει τίτλο «DISC ERROR» και για αυτό το σφάλμα.
- **Δοκιμή:** το `make test-multi`. Το DEMO τρέχει και αλλάζει χρώμα. Με F2 ο Launcher, και τρέχει το PONG. Ξανά στον Launcher, το DEMO συνεχίζει με το ίδιο χρώμα και κλείνει με ^Q. Το PONG συνεχίζει. Το STUDIO δεν ξεκινά και βγαίνει το σφάλμα 13.
- **Λάθος που βρέθηκε:** το μήνυμα σε μία γραμμή (27 χαρακτήρες) έκανε τον διάλογο φαρδύτερο από την οθόνη σε mode 0. Δεν φαινόταν, και ο βρόχος του περίμενε κουμπί. Βρέθηκε με dump της στοίβας και των μεταβλητών του διαλόγου (`TEST_DUMP`, `TEST_DUMP_AT`).

**Υλοποίηση M31 (VROUVES):**
- **Makefile:**
  - Το `myapp_rule` χτίζει με `-I <φάκελος>`, και έχει ως προαπαιτούμενα όλα τα `<φάκελος>/*.asm`.

- **Εισβολείς** (16 bytes, ως 16): θέση σε μονάδες 1/12 του κελιού, ταχύτητα ×16, επιβράδυνση από τη Γιαγιά. **Αμυντικοί** (4 bytes, ως 48): είδος, στήλη, γραμμή, αναμονή. Εμβέλεια με dx² + dy² ≤ r², στόχος ο εισβολέας που έχει προχωρήσει περισσότερο.

- **Desktop:** το `dt_play` ζωγραφίζει δίπλα στη σελίδα ενός `.VBN` ένα τρίγωνο ▶ από έξι στήλες (ύψους 11, 9, …, 1), στο χρώμα της σελίδας.
- **Studio:** η ΕΚΤΕΛΕΣΗ γράφει `VBN` στο FCB. Ο έλεγχος για το όνομα STUDIO αφαιρέθηκε, οπότε το Studio κέρδισε μερικά bytes.

**Υλοποίηση M19 (προγράμματα στο παρασκήνιο):**
- **Επιλογή του προγράμματος, API 9:** το `VOS_BACKGROUND` (κλήση 39, A = 1 συνεχίζει, 0 παγώνει) γράφει το `SLOT_FLAGS`, το byte 15 της θέσης του (`slot_bg`, kernel extension). Μια νέα θέση ξεκινά με 0 (`slot_alloc`), άρα ένα πρόγραμμα που δεν την καλεί παγώνει όπως πριν. Το accessory και ένα πρόγραμμα χωρίς θέση (όλη η bank 5) δεν αλλάζουν τίποτα.
- **Frames στο παρασκήνιο (`bg_frame`, στον βρόχο του kernel μετά το frame αυτού που είναι μπροστά):**
  - Για κάθε θέση με το bit, εκτός από το πρόγραμμα που είναι μπροστά (όψη `VIEW_APP` χωρίς ανοιχτό accessory), το `bg_find` κάνει το πρόγραμμα «του kernel» για ένα γεγονός: bank σπιτιού (μέσω του `ext_home`, που το `ext_call` επιλέγει όταν γυρίζει), `vw_cfg`, `app_slot`, `cur_base`. Ο kernel του στέλνει `EV_FRAME` με το `cur_call`, και το `bg_next` επαναφέρει αυτό που είναι μπροστά.
  - Ένα πρόγραμμα στο παρασκήνιο παίρνει frame σε κάθε frame, ανεξάρτητα από το `VOS_TICKS`, και κανένα άλλο γεγονός.
- **Σιωπηλές κλήσεις:** πριν από το πρώτο τέτοιο γεγονός σε ένα frame, το `bg_hush` κρατά τον πίνακα του API (120 bytes, στο extension) και γράφει `api_quiet` (`xor a`, `ret`: A = 0, Z, χωρίς carry) σε όλες τις κλήσεις εκτός από τις `VOS_FRAMES`, `VOS_RANDOM`, `VOS_KEEP`, `VOS_BACKGROUND` (`bg_quiet`). Στο τέλος ο πίνακας ξαναγράφεται.
  - Έτσι ένα πρόγραμμα πίσω δεν ζωγραφίζει, δεν αλλάζει mode, παλέτα, μενού, κουμπιά, κείμενα ή `VOS_TICKS` αυτού που είναι μπροστά, δεν παίζει ήχο, δεν διαβάζει πλήκτρα (το `VOS_KEY_HELD` δίνει Z), δεν πιάνει τον δίσκο ή τη bank δεδομένων (του Studio), και δεν τερματίζεται (`VOS_EXIT`).
  - Ο kernel μεγάλωσε κατά 44 bytes (τελειώνει στο `#3CE8`), το extension κατά περίπου 330.
- **Runtime των blocks:** το `rt_init` καλεί `VOS_BACKGROUND` με το `PROG_RUNS` (θέση `rt_runs_1`). Στη συνέχιση (A = 2) ζωγραφίζει τα πάντα όπως έχουν γίνει. Το `vbc.py` γράφει `PROG_RUNS` από το `"freeze"` του `.vbp` (true αν λείπει)· ο editor έχει το κουτάκι «Παγώνει στο παρασκήνιο».
- **Ο παίκτης:** το bit 6 του byte φόντου του `.VBS` (`V_RUNS`) γίνεται `rt_runs_1`. Το `RT_ALONE` καταργήθηκε: με `init` A = 2 ο παίκτης δεν ξαναμεταγλωττίζει (θα χαλούσε τα κοστούμια, που γίνονται εικόνες επί τόπου) αλλά πηγαίνει κατευθείαν στο `rt_init`. Τα προγράμματα του Studio συνεχίζουν πλέον σωστά από το F6.
- **Studio:**
  - STUDIO > ΣΤΟ ΠΑΡΑΣΚΗΝΙΟ (`CMD_BEHIND`): διάλογος με την τωρινή επιλογή και ερώτηση ΝΑΙ/ΟΧΙ για την άλλη. Το ESC είναι ΟΧΙ. Το ΦΟΝΤΟ κρατά πλέον και το `V_RUNS`.
  - Ο παίκτης δεν είναι πια μέσα στο `STUDIO.BIN`. Η ΕΚΤΕΛΕΣΗ φορτώνει το `VBRUN.SYS` από τον A: στη bank δεδομένων (`VOS_LOAD` + `VOS_DATA`, BC = μέγεθος) και γράφει το πρόγραμμα αμέσως μετά. Το ΑΝΟΙΓΜΑ διαβάζει πλέον στο `#4000` της bank δεδομένων.
  - Ο χώρος του `.VBS` (5K) δεν αποθηκεύεται στο αρχείο, που έγινε 11K. Το Studio κέρδισε 285 bytes και έχει 145 ελεύθερα.
  - Η επέκταση `.SYS` κρατά τον παίκτη έξω από τον Launcher.
- **`tools/mktexts.py`:** οι στήλες χωρίζονται με «|» ανάμεσα σε κενά, ώστε και τα αγγλικά κείμενα να έχουν αλλαγή γραμμής σε διάλογο.
- **`tools/mkvbs.py`:** `BEHIND PAUSE` ή `BEHIND RUN`.
- **Δοκιμή:** το `make test-behind`, με 576K.
  - Στο Studio, ΣΤΟ ΠΑΡΑΣΚΗΝΙΟ δείχνει «ΤΟ ΠΡΟΓΡΑΜΜΑ ΕΚΕΙ ΠΑΓΩΝΕΙ»· μετά το ΝΑΙ, ο ίδιος διάλογος δείχνει «ΤΡΕΧΕΙ».
  - Το `TICKER` (`blocks/examples/ticker.vbt`) ξεκινά και μετρά. Ο Launcher και μετά το DEMO μπροστά του μένουν καθαροί.
  - Το F6 δείχνει STUDIO, TICKER, > DEMO. Το TICKER ξαναβγαίνει με τον μετρητή να έχει προχωρήσει όσο ήταν πίσω, και τη μπάλα αλλού.
  - Τα άλλα tests περνούν. Στο test-calc το ΑΝΟΙΓΜΑ θέλει τρία UP ακόμα, για τα TICKER.BIN, TICKER.VBS και VBRUN.SYS στο τέλος της λίστας.
- **Όρια:** όσο τρέχει διάλογος, μενού, το παράθυρο του F6 ή ο δίσκος, ο βρόχος του kernel δεν τρέχει, οπότε και τα προγράμματα στο παρασκήνιο περιμένουν. Ένα πρόγραμμα του Studio χρειάζεται επέκταση μνήμης για να είναι πίσω από άλλο.

**Υλοποίηση M18 (επέκταση μνήμης):**
- **Ανίχνευση (`src/boot/expand.asm`, `xb_detect`):**
  - Τρέχει από τον loader, μετά το kernel extension και πριν μηδενιστεί η μνήμη της οθόνης. Βρίσκεται στο `VOS.BIN` στο `#8800`, έξω από το παράθυρο που αλλάζει.
  - Γράφει στην πρώτη bank κάθε μπλοκ 64K (`#C4 + μπλοκ × 8`) τον αριθμό του, από το 7 ως το 0 (bank 4), και μετά τους διαβάζει.
  - Ένα μπλοκ που δεν υπάρχει δείχνει άλλον αριθμό, γιατί έγραψε στην ίδια μνήμη κάποιο που ακολούθησε. Σε 6128 χωρίς επέκταση όλα πέφτουν στη bank 4.
  - Οι τέσσερις banks κάθε μπλοκ που βρέθηκε μπαίνουν στο `bk_list` (bank 7), μετά τη bank 5. Ως 28 banks.
- **Θέσεις:** ο πίνακας μεταφέρθηκε από τα κρυφά κενά στο kernel extension: 15 εγγραφές των 16 bytes στο `#7F10–#7FFF` (`SLOT_TABLE`).
  - Πεδία κάθε εγγραφής: πρώτη σελίδα, σελίδες, μονάδα, όνομα, και `SLOT_CFG`, η RAM config της bank του.
  - Το `app_slot` και το `app_wake` κρατούν πλέον τον αριθμό της εγγραφής, 1–15.
  - Όλος ο κώδικας των θέσεων είναι στο extension: `app_place`, `slot_alloc`, `slot_wake`, `slot_own`, `slot_free` και `slot_find` (για τον Launcher). Στη σελίδα μηδέν έμειναν μόνο τα `reloc_find` και `reloc`.
  - Το `ext_call` επιστρέφει πλέον το A και τα flags της ρουτίνας.
- **Τοποθέτηση (`slot_alloc`):** first-fit σε κάθε bank του `bk_list`, από το `#50` στη bank 5 και από το `#40` στις άλλες.
  - Ένα πρόγραμμα με πίνακα μετακινείται όπου χωρά (στο `#4000` δεν χρειάζεται relocation).
  - Ένα χωρίς πίνακα θέλει 64 σελίδες από το `#40`, δηλαδή μια άδεια bank της επέκτασης.
  - Αν δεν χωρά πουθενά και δεν τρέχει τίποτα, παίρνει όλη τη bank 5 χωρίς θέση, όπως πριν. Αλλιώς βγαίνει το σφάλμα 13.
- **Η bank του προγράμματος:** ο kernel δεν υποθέτει πια τη bank 5. Το `vw_cfg` είναι η bank αυτού που τρέχει (`view_install`, συνέχιση, κλείσιμο του accessory, `VOS_BANK_GET`/`PUT`, `VOS_LOAD`/`SAVE`).
- **Bank δεδομένων:** μένει η bank 4 για όλους. Το Studio, το μόνο που τη χρησιμοποιεί, ξαναβάζει τον player σε κάθε `init`.
- **Μικτή οθόνη και ήχος:** το `view_start` τα σταματά, ώστε η μικτή οθόνη του Studio ή του MIXED να μη μένει σε ό,τι ακολουθεί. Ό,τι συνεχίζει τα ξαναθέτει στο `init`.
- **Δοκιμή:** το `make test-expand`, με Caprice32 στα 576K (`VOS_RAM=576` στο `tools/cap32_shot.sh`).
  - Τρέχουν μαζί STUDIO (bank της επέκτασης), DEMO και PONG (bank 5) και CALC (άλλη bank της επέκτασης).
  - Το F6 τα δείχνει και τα τέσσερα. Το STUDIO ξαναβγαίνει, και το DEMO συνεχίζει.
  - Τα test-switch και test-multi, με 128K, δείχνουν τα ίδια με το M17.
- **Όρια:** το Studio στη συνέχιση ξεκινά από την αρχή (ξανανοίγει το αρχείο που αποθηκεύτηκε τελευταίο). Το F6 δείχνει ως 8 προγράμματα.

**Υλοποίηση M17 (εναλλαγή προγραμμάτων):**
- **Πλήκτρο:** το F6, έξω από μενού, από κάθε όψη ή πρόγραμμα (`view_keys`). Δεν ανοίγει όσο είναι ανοιχτό το accessory.
- **Μενού:** στο κοινό μενού VIEW των όψεων το PROGRAMS (`CMD_PROGRAMS`), που κάνει το ίδιο.
- **Παράθυρο ΠΡΟΓΡΑΜΜΑΤΑ (`sw_run`):**
  - Δείχνει τα προγράμματα στις θέσεις τους, με τη σειρά που ξεκίνησαν (το `slot_alloc` παίρνει την τελευταία ελεύθερη θέση, οπότε το `sw_run` τις διαβάζει από το τέλος).
  - Το όνομα εμφανίζεται χωρίς επέκταση. Το πρόγραμμα που τρέχει έχει «>» και είναι επιλεγμένο το επόμενο, όπως στο Alt+Tab.
  - Το F6, το DOWN και το UP μετακινούν την επιλογή κυκλικά. Το RETURN, το ENTER, το SPACE ή ένα κλικ τη διαλέγουν. Το ESC ή ένα κλικ έξω από το παράθυρο το κλείνουν.
  - Το πρόγραμμα που διαλέγεις συνεχίζει όπως από τον Launcher: το `sw_run` γράφει μονάδα και όνομα από τη θέση στα `app_drive` και `file_name` (το `app_run` τα αντιγράφει στο `app_self`), και τη θέση στο `app_wake`.
  - Χωρίς προγράμματα βγαίνει ο διάλογος «NO PROGRAM|IS RUNNING».
- **Kernel extension:** ο kernel δεν είχε χώρο (137 bytes, 10 στη μεγαλύτερη δοκιμαστική έκδοση).
  - Κώδικας που δεν χρειάζεται να είναι πάντα ορατός μπαίνει πλέον στη bank 7 στο `#7800` (`EXT_ADDR`, ως 2K, `src/kernel/ext.asm`). Τα αγγλικά κείμενα περιορίστηκαν σε 4K: το `ENGLISH.MSG` είναι 1,5K.
  - Στο `VOS.BIN` βρίσκεται στο `#8000` (`EXT_IMAGE`). Ο loader το αντιγράφει με το `bank_put` πριν μηδενίσει τη μνήμη της οθόνης.
  - Ο kernel το καλεί με το `ext_call` (HL = ρουτίνα). Όσο τρέχει, η bank 7 είναι η bank «σπιτιού» (`ram_home_cfg`), άρα οι ρουτίνες του kernel που αλλάζουν bank την ξαναφέρνουν. Δεν πρέπει να αγγίζει τη μνήμη μιας όψης.
  - Εκεί μεταφέρθηκε και το `lang_init` (190 bytes, μόνο στην εκκίνηση). Το extension πιάνει 704 bytes και ο kernel τελειώνει στο `#3CE3`.
- **Κείμενα:** το `LANG_MSG_MAX` ανέβηκε από 127 σε 159, γιατί το ελληνικό ΠΛΗΚΤΡΑ με το F6 έγινε 140 χαρακτήρες. Τα buffers τελειώνουν ως το byte 704 των κενών των 800.
- **Δοκιμή:** το `make test-switch`.
  - Το F6 στο Desktop δείχνει «NO PROGRAM IS RUNNING».
  - Τρέχουν το DEMO (που αλλάζει χρώμα) και το PONG. Το F6 από το PONG δείχνει «DEMO, > PONG» με επιλεγμένο το DEMO, και το RETURN συνεχίζει το DEMO με το ίδιο χρώμα.
  - Δύο F6 από το DEMO γυρίζουν την επιλογή, και το ESC κλείνει το παράθυρο.
  - Στον Commander, το VIEW → PROGRAMS δείχνει τη λίστα χωρίς «>». Με DOWN και RETURN συνεχίζει το PONG.

**Υλοποίηση M10 (εικονίδια):**
- **Μορφή:** προαιρετική. Στο `+12` (`VOS_ICON`) ένα πρόγραμμα βάζει `"IC"` και 256 bytes: 16 γραμμές × 8 ζεύγη (μάσκα, pixels), όπως τα σχεδιάζει το `VOS_BLIT`. Είναι 16×16 pixels σε mode 0, με την παλέτα του Launcher, και το `init` ξεκινά στο `+270`.
- **Πηγή:** κείμενο, 16 γραμμές των 16 χαρακτήρων: πένα σε hex ή `.` για διάφανο. Το `tools/mkicon.py` το κάνει assembly. Τα εικονίδια των προγραμμάτων είναι στο `apps/icons/`.
- **Τα προγράμματα με blocks:** το `vbc.py` βάζει το `"icon"` του `.vbp` (16 γραμμές, όπως τα κοστούμια), αλλιώς το `apps/icons/blocks.txt`. Ο παίκτης του Studio έχει το ίδιο, οπότε το έχουν και τα `.BIN` του Studio.
- **Launcher:**
  - Την πρώτη φορά που ζωγραφίζεται μια σελίδα, διαβάζει το πρώτο sector κάθε `.BIN` της. Ο κατάλογος είναι ήδη στη μνήμη, άρα κοστίζει ένα sector ανά πρόγραμμα.
  - Αν το αρχείο έχει header AMSDOS, `"VA"` και `"IC"`, κρατά το εικονίδιο σε μια σελίδα 256 bytes μετά τον κώδικά του (ως 50 προγράμματα, εκτός αρχείου της όψης).
  - Μετακινήσεις μέσα στη σελίδα δεν ξαναδιαβάζουν τον δίσκο. Το όνομα και ο τύπος κατέβηκαν 4 γραμμές.
- **Kernel:** ο Launcher χρησιμοποιεί κατευθείαν τις ρουτίνες του `fs.asm`.
- **Διόρθωση της μικτής οθόνης (`split_irq`):**
  - Ένα interrupt VSYNC που εξυπηρετείται αργά (μετά από μεταφορά δίσκου) δεν βλέπει το VSYNC, και η αρίθμηση των interrupts μετατοπίζεται.
  - Αν η αναμονή του y1 (45 γραμμές) πέσει τότε στο interrupt πριν από το VSYNC, κάθε επόμενο interrupt VSYNC καθυστερεί κι αυτό, και το λάθος μένει.
  - Μετά τις αναμονές, αν το VSYNC είναι ενεργό εκτός του interrupt 0, το επόμενο interrupt μετρά ως 0.
  - **Διορθώθηκε (μετά το M12):** το λάθος δεν ήταν στο VSYNC (η μέτρηση του M11 γινόταν μέσα από interrupts που αργούσαν).
    - Ο handler βλέπει το VSYNC μόνο αν εξυπηρετήσει το interrupt του μέσα σε περίπου 3 γραμμές.
    - Με λάθος αρίθμηση, μια φέτα με την αναμονή των 45 γραμμών μπορούσε να καθυστερεί το interrupt του VSYNC σε κάθε frame. Έτσι το VSYNC δεν φαινόταν ποτέ, και το `int_frames` και το `wait_frame` σταματούσαν.
    - Τώρα, μετά από 12 interrupts χωρίς VSYNC (`INT_BLIND_MAX`), ο handler το περιμένει ενεργά μία φορά (ως ένα frame) και ξαναμετρά από εκεί. Δεν το κάνει όσο ο δίσκος μεταφέρει τομείς (`fdc_idle_count` < 3).
    - Εργαλεία: `-DTEST_TRACE` και `-DTEST_DUMP` (`src/kernel/test_script.asm`).

## 8. Γλώσσα τύπου Scratch και μεταγλωττιστής

### 8.1 Πού τρέχει ο editor

**Απόφαση:** πρώτα editor σε PC (cross-compiler). Ο native editor μέσα στο V-OS έρχεται αργότερα, αν έρθει.

- **Φάση 1 (προτείνεται):** editor σε PC (web, π.χ. με Blockly) που παράγει Z80 assembly, το οποίο μεταγλωττίζεται με RASM ή sjasmplus και γράφεται σε εικόνα `.DSK`. Γρήγορη ανάπτυξη και εύκολος έλεγχος του παραγόμενου κώδικα.
- **Φάση 2:** native editor μέσα στο V-OS (πρότυπο D, «Studio»), που αποθηκεύει `.VBP` και μεταγλωττίζει επί τόπου σε `.BIN`. Πολύ πιο απαιτητικό σε μνήμη και χρόνο ανάπτυξης.

**Υλοποίηση M8b** (`apps/studio/studio.asm`, πρόγραμμα `STUDIO`):
- **Οθόνη:** μικτή, με όριο στη γραμμή 138.
  - Σε mode 0: η σκηνή σε μισό μέγεθος και η λίστα αντικειμένων.
  - Σε mode 1, 48 στήλες: παλέτα, script και γραμμή κατάστασης.
  - Η διάταξη του προτύπου D (όλα σε mode 0) δεν χωρούσε: με γράμματα 8 pixels το mode 0 έχει μόνο 24 στήλες.
- **Αποθήκευση `.VBS` αντί για `.VBP`:** ένα JSON θα ήθελε parser στον Z80. Η δυαδική μορφή είναι:
  - κεφαλίδα `"VBS",1`, πένα φόντου και ως 6 αντικείμενα (x, y, w, h, χρώμα),
  - μετά γραμμές των 10 bytes: block και τρία πεδία (είδος, τιμή 16 bit).
  Τα blocks είναι ένα υποσύνολο του §8.2: 24 blocks σε 5 κατηγορίες, μεταβλητές A–H, συγκρίσεις χωρίς τελεστές πράξεων.
- **Εσοχή:** τα blocks που ανοίγουν κλείνουν με γραμμή `END` (`ΤΕΛΟΣ`), οπότε η δομή βγαίνει από τη σειρά των γραμμών, χωρίς δέντρο.
- **Kernel:** με ενεργό split, οι διάλογοι κεντράρονται στη ζώνη mode 0 (`ui_centre`), και η λίστα αρχείων δείχνει 8 γραμμές.

**Υλοποίηση M11 (μηνύματα):** δύο ακόμα blocks, `ΟΤΑΝ ΛΑΒΕΙ n` (ξεκινά script, `EVT_RECEIVE` του runtime) και `ΣΤΕΙΛΕ n` (`rt_broadcast`, το n είναι οποιαδήποτε τιμή). Είναι οι αριθμοί 24 και 25, μετά τα παλιά, οπότε τα αρχεία `.VBS` μένουν συμβατά. Η παλέτα τα δείχνει στα ΓΕΓΟΝΟΤΑ μέσω του πίνακα `pal_order`.

**Υλοποίηση M12 (πράξεις, παράθυρα, κουμπιά):**
- **Blocks 26–33:** `ΜΕΙΩΣΕ`, `ΠΟΛΛΑΠΛΑΣΙΑΣΕ`, `ΔΙΑΙΡΕΣΕ`, `ΥΠΟΛΟΙΠΟ` (με τα `rt_mul`, `rt_div`, `rt_mod` του runtime), `ΠΑΡΑΘΥΡΟ`, `ΚΟΥΜΠΙ`, `ΟΤΑΝ ΚΟΥΜΠΙ` (`EVT_BUTTON`), `ΚΕΙΜΕΝΟ`. Η τιμή `ΚΟΥΜΠΙ` (`K_BUTTON`) είναι ο αριθμός του τελευταίου κουμπιού.
- **Κείμενα:** ένα νέο είδος πεδίου, `K_TEXT`, δείχνει ένα από τα 32 κείμενα του προγράμματος (16 bytes το καθένα). Το Studio δίνει σε κάθε νέο block ένα ελεύθερο κείμενο, δηλαδή ένα που δεν το χρησιμοποιεί καμία γραμμή, και το γράφει με το `VOS_INPUT`.
- **Μορφή `.VBS` 2:** `"VBS",2`, φόντο, αντικείμενα, μετά 32 × 16 bytes κείμενα, πλήθος γραμμών, γραμμές. Το OPEN διαβάζει και τη μορφή 1 και κάνει χώρο για τα κείμενα.
- **Παράθυρα και κουμπιά στον παίκτη:**
  - Υπάρχουν μόνο με το `RT_UI` στο `runtime.asm`, οπότε το `vbc.py` βγάζει τον ίδιο κώδικα.
  - Το παράθυρο σχεδιάζεται με `VOS_RECT` και `VOS_PRINT`, στα χρώματα των διαλόγων σε mode 0.
  - Τα κουμπιά είναι του kernel (`VOS_SET_WIDGETS`). Οι εντολές τους ξεκινούν από το `RT_CMD_BUTTON`, και τα κείμενά τους είναι κείμενα του προγράμματος (`VT_FIRST + 2 + n`).
  - Ένα νέο παράθυρο σβήνει το προηγούμενο και τα κουμπιά του. Το `rt_redraw` τα ξανασχεδιάζει.
  - Οι κλήσεις του kernel γίνονται στη στοίβα του kernel (`rt_on_main`).
- **`vbc.py` και editor (μετά το M12):** τα ίδια blocks: `window`, `button`, το γεγονός `button` και η τιμή `{"button": true}` στο `.vbp`. Ο κώδικας (`rt_window`, `rt_button`, `rt_write`) μεταφέρθηκε από τον παίκτη στο `runtime.asm`, μέσα στο `RT_UI`. Το πρόγραμμα δίνει τα `rt_texts` και `rt_text_ptr`, και το `rt_ui_width` είναι το πλάτος της οθόνης. Με παράθυρο, το `print` μετρά από το εσωτερικό του (`rt_ox`, `rt_oy`).
- **Kernel:** όταν ξεκινά μια όψη ή ένα πρόγραμμα, τα κουμπιά του προηγούμενου ξεχνιούνται (`view_install`).
- **Κείμενα του Studio:** τα κείμενα των blocks είναι σε δεύτερο πίνακα (`apps/studio/blocks.txt`, `block_texts`). Το Studio αλλάζει πίνακα με το `VOS_TEXTS` μόνο για αυτά (`block_text`), γιατί το όριο είναι 64 κείμενα ανά πίνακα.
- **Mode 1:** το bit 7 του byte φόντου (`V_MODE1`) λέει ότι το πρόγραμμα τρέχει σε mode 1.
  - Το runtime έχει το mode και το πλάτος ως τιμές που αλλάζουν (`rt_mode_1`, `rt_width_1..4`), και ο player τις ορίζει όταν ξεκινά (192 ή 384 pixels).
  - Ο player δεν είχε κοστούμια στο M12, άρα οι εικόνες (που θέλουν το mode από τη μεταγλώττιση) δεν τον αφορούσαν. Στο M13 τα απέκτησε (παρακάτω).
  - Το Studio μετρά τη σκηνή σε pixels του mode του προγράμματος. Όταν το πρόγραμμα γυρίσει σε mode 0, τα αντικείμενα μένουν μέσα στα 192 pixels.
- **Kernel, αυτόματη επανάληψη (`kbd.asm`):** επανάληψη πλήκτρου στέλνεται μόνο όταν η ουρά συμβάντων είναι άδεια. Πριν, μια όψη που αργούσε, όπως η λίστα αρχείων όταν κυλά, γέμιζε την ουρά, και τα πλήκτρα μετά (RETURN) χάνονταν (`ev_dropped`). Στη δοκιμή του Studio αυτό φάνηκε σαν κόλλημα: το κλικ που ακολουθούσε διάλεγε άλλο αρχείο, και το σφάλμα έβγαινε σε διάλογο που δεν φαινόταν πάνω στη μικτή οθόνη. Για τέτοια ψαξίματα, το `-DTEST_DUMP=frame` (μόνο στα builds δοκιμής) δείχνει τη στοίβα ή 96 bytes μνήμης (`-DTEST_DUMP_AT`, δεκαδικός αριθμός) ως bits στην πάνω γραμμή της οθόνης.

**Υλοποίηση M13 (κοστούμια στο Studio):**
- **Δεδομένα:** ως 8 κοστούμια των 16×16 pixels ανά πρόγραμμα, κοινά για όλα τα αντικείμενα. Ένα byte ανά pixel: η πένα, ή `#80` για κανένα (διάφανο). Το byte 7 κάθε αντικειμένου (πριν μηδέν) είναι το κοστούμι του: 0 κανένα (ορθογώνιο), 1..8.
- **Μορφή `.VBS` 3:** μετά τις γραμμές, `db` πλήθος, και ανά κοστούμι `db 0, 0` και 256 pixels (258 bytes). Το ΑΝΟΙΓΜΑ διαβάζει και τις μορφές 1 και 2, χωρίς κοστούμια.
- **Στη μνήμη του Studio** τα κοστούμια είναι σε σταθερή θέση, μετά τον χώρο των 200 γραμμών, ώστε οι γραμμές να μεγαλώνουν χωρίς να τα μετακινούν. Η ΑΠΟΘΗΚΕΥΣΗ και το RUN τα αντιγράφουν προσωρινά αμέσως μετά τις γραμμές (`vbs_bytes`) και μετά τα επαναφέρουν (`cos_unpack`).
- **Επεξεργαστής:** παίρνει τη θέση της σκηνής στη ζώνη mode 0. Πλέγμα 16×16 κελιών των 4×7 pixels, από κάτω η σειρά με τις 16 πένες, δεξιά ο τίτλος και η πένα.
  - Πλήκτρα: βελάκια, SPACE ή RETURN για βάψιμο, `0`–`9`, `A`–`F` για πένα, `.` για καμία, E ή TAB για τέλος.
  - Ποντίκι: κλικ σε κελί το βάφει, κλικ στη σειρά διαλέγει πένα.
- **Σκηνή:** K αλλάζει το κοστούμι του αντικειμένου (κανένα, 1, 2, …), E το σχεδιάζει (νέο αν δεν έχει). Η σκηνή δείχνει το κοστούμι στο μισό μέγεθος, ένα pixel στα δύο (σε mode 1 ένα στα τέσσερα οριζόντια).
- **Blocks 34–35:** `ΚΟΣΤΟΥΜΙ n` (από 1· το 0 δεν αλλάζει τίποτα) και `ΕΠΟΜΕΝΟ ΚΟΣΤΟΥΜΙ`. Η τιμή `ΚΟΣΤΟΥΜΙ` (`K_COSTUME`, γράμμα U) δίνει τον αριθμό του, 0 για ορθογώνιο. Είναι τα ίδια με τα `switch_costume`, `next_costume` και `{"costume": true}` του `vbc.py`, που δέχεται πλέον και τιμή στο `"to"`.
- **Παίκτης:** διαβάζει τα κοστούμια μετά τις γραμμές και τα κάνει εικόνες του `VOS_BLIT` επί τόπου (`pl_costumes`, `pl_image`), για το mode του προγράμματος, οπότε δεν χρειάζεται άλλη μνήμη. Ο κώδικας γράφεται μετά τα κοστούμια.
  - Όλα τα αντικείμενα έχουν τον ίδιο πίνακα κοστουμιών (`pl_ctab`).
  - Το runtime, με `RT_ANY_MODE`, έχει θέσεις (`rt_m1_*`) για τις λίγες εντολές των εικόνων που εξαρτώνται από το mode. Ο παίκτης γράφει εκεί τις εντολές του mode 1 όταν το πρόγραμμα είναι σε mode 1.
- **Μέγεθος:** το Studio γέμισε τη bank του (μένουν 6 bytes). Επόμενες προσθήκες θα χρειαστούν χώρο από αλλού, π.χ. κείμενα ή κώδικα στη bank δεδομένων.
- **`tools/mkvbs.py`:** μορφή 3, `IMAGE` με 16 γραμμές pixels, και κοστούμι ως 6ο αριθμό στο `SPRITE`. Παράδειγμα: `blocks/examples/flap.vbt`.
- **Kernel:** στη λίστα αρχείων (`file_pick`) το UP από το πρώτο πάει στο τελευταίο και το DOWN από το τελευταίο στο πρώτο.

**Υλοποίηση M8c** (`blocks/player.asm`, εντολή ΕΚΤΕΛΕΣΗ του Studio):
- **Ο παίκτης (`VBRUN`):** το runtime του M7 (`blocks/runtime.asm`) σε mode 0, μαζί με έναν μεταγλωττιστή για τις γραμμές του `.VBS`. Είναι 3,7K, και το Studio τον έχει μέσα του (`incbin`).
- **ΕΚΤΕΛΕΣΗ (CONTROL+R):**
  - Αποθηκεύει το `ΟΝΟΜΑ.VBS`.
  - Γράφει το `ΟΝΟΜΑ.BIN`: τον παίκτη και αμέσως μετά το πρόγραμμα. Στη μνήμη του Studio ο buffer του `.VBS` είναι ακριβώς μετά τον παίκτη, οπότε αρκεί ένα `VOS_SAVE`.
  - Το τρέχει με τη νέα κλήση `VOS_RUN`.
  - Όταν το πρόγραμμα σταματήσει (ΠΡΟΓΡΑΜΜΑ > ΤΕΛΟΣ), το Studio ξαναξεκινά και ανοίγει το ίδιο `.VBS`. Το όνομά του το κρατά ο kernel (`VOS_KEEP`).
  - Το `.BIN` είναι κανονικό πρόγραμμα: φαίνεται και στον Launcher.
- **Η μεταγλώττιση γίνεται όταν ξεκινά το `.BIN`, όχι μέσα στο Studio:**
  - Ο παίκτης γράφει κώδικα Z80 μετά τις γραμμές, τον ίδιο που βγάζει το `vbc.py` για τα ίδια blocks: κλήσεις στο runtime, άλματα για βρόχους και `ΑΝ`/`ΑΛΛΙΩΣ`, με μια στοίβα για τα blocks που είναι ανοιχτά.
  - Έτσι το Studio δεν χρειάζεται χώρο για τον κώδικα, και το πρόγραμμα έχει όλη την bank του.
- **Μνήμη του προγράμματος:** ο κώδικας ως το `#74C0`. Από το `#7500` τα αντικείμενα, ο πίνακας και η κατάσταση των scripts, οι μεταβλητές και οι μετρητές των `ΕΠΑΝΑΛΑΒΕ`. Από το `#7800` οι στοίβες, ως 16 scripts.
- **Κανόνες:**
  - Γραμμές πριν από το πρώτο `ΟΤΑΝ` δεν μετράνε, ούτε script για αντικείμενο που δεν υπάρχει.
  - Ένα script τελειώνει στο επόμενο `ΟΤΑΝ` ή στο τέλος, όπου κλείνουν τα blocks που μένουν ανοιχτά.
  - Σε script της σκηνής, τα blocks κίνησης και εμφάνισης δεν κάνουν τίποτα, και τα X, Y, ΑΓΓΙΖΕΙ, ΣΤΗΝ ΑΚΡΗ δίνουν 0.
- **Runtime:** οι αριθμοί των scripts και των αντικειμένων και η πένα φόντου είναι πλέον τιμές μέσα στις εντολές (`rt_nscripts_n`, `rt_nsprites_n`, `rt_bg_n`), που ο παίκτης γράφει όταν ξεκινά. Τα προγράμματα του `vbc.py` βγαίνουν ίδια byte προς byte.
- **API έκδοση 5** (37 κλήσεις):
  - `VOS_RUN` (A = μονάδα, HL → όνομα 11 bytes) τρέχει ένα πρόγραμμα. Όταν αυτό τελειώσει, ξαναξεκινά εκείνο που το κάλεσε.
  - `VOS_KEEP` δίνει 16 bytes που ο kernel κρατά από πρόγραμμα σε πρόγραμμα.
  - Αν ο χρήστης φύγει σε μια όψη (F1–F4), η επιστροφή στο πρόγραμμα που κάλεσε ακυρώνεται.
- **Το header AMSDOS του `.BIN`** έγραφε στο M8c ως διεύθυνση φόρτωσης τη θέση του παίκτη μέσα στο Studio. Από το M9 το `.BIN` γράφεται από τη bank δεδομένων και η διεύθυνση είναι `#4000`.

### 8.2 Γλώσσα

- Κατηγορίες blocks: κίνηση, εμφάνιση, ήχος, συμβάντα, έλεγχος, αισθητήρες, τελεστές, μεταβλητές.
- Τύποι: ακέραιοι 8 και 16 bit, boolean, σταθερά strings, λίστες σταθερού μεγέθους. Χωρίς floating point στην πρώτη έκδοση.
- Συμβάντα: `when start`, `when key`, `when click`, `when receive`, `broadcast`.
- Sprites: θέση, κατεύθυνση, κοστούμια, σύγκρουση με ορθογώνια.

### 8.3 Παραγωγή κώδικα

- Κάθε block αντιστοιχεί σε ένα πρότυπο assembly που καλεί το API ή μια μικρή runtime library.
- Πολλαπλά scripts (`forever`, παράλληλα events) υλοποιούνται ως **coroutines**: κάθε script έχει δική του στοίβα ή κατάσταση και κάνει `yield` στο τέλος κάθε επανάληψης. Αυτό δίνει τη συμπεριφορά του Scratch χωρίς preemptive multitasking.
- Απλή ανάθεση καταχωρητών, με μεταβλητές σε σταθερές θέσεις μνήμης. Βελτιστοποιήσεις (constant folding, peephole) αργότερα.
- Έξοδος: αρχείο `.ASM` (για διάβασμα και εκμάθηση) και `.BIN` με το header του V-OS.

### 8.4 Υλοποίηση (M7)

- **Editor:** `blocks/editor.html`, Blockly από CDN, ελληνικά και αγγλικά. Το `.vbp` είναι JSON με το πρόγραμμα μόνο. Ο editor μετατρέπει στις δύο κατευθύνσεις (blocks ↔ `.vbp`), οπότε το αρχείο είναι η μόνη πηγή.
- **Μεταγλωττιστής:** `blocks/vbc.py` (Python). Κάθε έκφραση αφήνει την τιμή της στο HL, και οι δυαδικοί τελεστές κρατούν το αριστερό μέλος στη στοίβα. Οι μεταβλητές και τα αντικείμενα είναι σε σταθερές διευθύνσεις. Κάθε πέρασμα βρόχου τελειώνει με `call rt_yield`.
- **Runtime:** `blocks/runtime.asm`. Κάθε script έχει στοίβα 128 bytes στη bank του προγράμματος. Μια κλήση του kernel που αλλάζει bank στο `#4000` (κείμενα συστήματος, μενού) θα έβγαζε τη στοίβα από τη μνήμη, γι' αυτό γίνεται στη στοίβα του kernel (`rt_clear`). Τα αντικείμενα είναι ορθογώνια με ταχύτητα: `move`, `bounce`, σύγκρουση, κλικ. Σβήνονται και ξανασχεδιάζονται μόνο όταν αλλάξουν.
- **M7b:** κοστούμια (εικόνες με μάσκα, `VOS_BLIT`), ήχος (driver AY, `VOS_SOUND`, νότες MIDI), λίστες αριθμών με σταθερό μέγιστο μήκος. Τα αντικείμενα κόβονται στις άκρες της σκηνής. Το API είναι πλέον στην έκδοση 3.
- **Από το §8.2 μένουν:** κατεύθυνση (υπάρχει μόνο ταχύτητα vx/vy), strings ως τιμές.

## 9. Εργαλεία ανάπτυξης και δοκιμές

- **Assembler:** RASM (γράφει απευθείας σε `.DSK`, υποστηρίζει banks του CPC) ή sjasmplus.
- **Emulators:** ACE-DL ή CPCEC (επιλογή τύπου CRTC, ακριβής χρονισμός), WinAPE (debugger), Retro Virtual Machine.
- **Εικόνες δισκέτας:** `iDSK` ή RASM για δημιουργία και επεξεργασία `.DSK`.
- **Build:** Makefile που μεταγλωττίζει kernel, εφαρμογές και δημιουργεί `VOS.DSK`.
- **Δοκιμές:** σε όλους τους τύπους CRTC (0, 1, 2) στον emulator, σε πραγματικό 6128 με 3" και με Gotek/HxC, και ειδικά για το AMX Mouse.
- **Repo:** `src/kernel`, `src/drivers` (fdc, kbd, mouse, crtc), `src/gfx`, `src/ui`, `src/apps`, `compiler/`, `docs/`, `tools/`.

## 11. Προτεινόμενα ορόσημα

1. **M0 — Υποδομή:** repo, Makefile, RASM, εκκίνηση από `RUN"VOS"`, απενεργοποίηση ROM, δικός interrupt handler.
2. **M1 — Οθόνη:** overscan σε mode 1 και mode 0, παλέτα, plot/rect/text, γραμματοσειρά ASCII.
3. **M2 — Είσοδος:** πληκτρολόγιο με ουρά συμβάντων, pointer από cursor keys και AMX Mouse, δείκτης λογισμικού.
4. **M2b — Γλώσσες:** μορφή `.LNG`, `tools/mklng`, ελληνικό pack (γραμματοσειρά, keymap, μηνύματα), εναλλαγή EN/EL.
5. **M3 — UI:** γραμμή μενού, πτυσσόμενα μενού, εστίαση και TAB, διάλογοι.
6. **M4 — Δισκέτα:** driver FDC (read/write sector), filesystem συμβατό με AMSDOS (catalog, load, save, delete), παράθυρο επιλογής αρχείου. Το format μένει για αργότερα.
7. **M5 — Shell:** πρώτα το Commander (C, μόνο κείμενο, γρηγορότερο να γίνει), μετά το Desktop (A) με παράθυρα, τέλος ο Launcher (B) σε mode 0. Εναλλαγή όψεων και Setup. *M5a (έγινε): Commander με δύο πάνελ, στοιχεία, αντιγραφή, διαγραφή. M5b (έγινε): όψεις ως overlays, Desktop, Launcher, μετονομασία, αντιγραφή αρχείων κάθε μεγέθους. M5c (έγινε): Setup και `SETUP.CFG`, format, επιβεβαίωση αντικατάστασης, η επιλογή μένει από όψη σε όψη. Μένει η εκκίνηση προγραμμάτων από τον Launcher (M6).*
8. **M6 — API και loader:** jump table, header εφαρμογών, banks, πρώτη εφαρμογή-δείγμα. *Έγινε: API 31 κλήσεων, loader, εκκίνηση από Launcher/Desktop/Commander, `DEMO.BIN`. Ο ήχος ήρθε στο M7b, η bank δεδομένων για προγράμματα στο M9 (§7.2), τα εικονίδια στο M10 (§7.3), το relocation στο M14.*
9. **M7 — Cross-compiler:** web editor blocks → ASM → `.BIN` σε `.DSK`. *Έγινε: editor με Blockly, `vbc.py`, runtime με coroutines, παραδείγματα PONG και CATCH. M7b: κοστούμια, ήχος, λίστες, παράδειγμα STARCAT (§8.4).*
10. **M8 — Studio:** μικτή οθόνη και native editor (προαιρετικό). *M8a (έγινε): μικτή οθόνη με `VOS_SPLIT`, μενού και δείκτης ανά ζώνη, πρόγραμμα `MIXED` (§2.3). M8b (έγινε): ο editor `STUDIO`, με αρχεία `.VBS` (§8.1). M8c (έγινε): ΕΚΤΕΛΕΣΗ από το Studio, με τον παίκτη `VBRUN` που μεταγλωττίζει το πρόγραμμα όταν ξεκινά, και `VOS_RUN`/`VOS_KEEP` (API 5).*
11. **M9 — Bank δεδομένων για προγράμματα:** η bank 4 είναι του προγράμματος όσο τρέχει, με `VOS_BANK_GET`/`VOS_BANK_PUT` και φόρτωση/αποθήκευση αρχείων σε αυτή (API 6, §7.2). *Έγινε· το Studio κρατά εκεί τον παίκτη.*
12. **M10 — Εικονίδια προγραμμάτων:** εικονίδιο 16×16 στο header (`VOS_ICON`), `tools/mkicon.py`, ο Launcher τα δείχνει στις κάρτες (§7.3). *Έγινε.*
13. **M11 — Μηνύματα στο Studio:** `ΟΤΑΝ ΛΑΒΕΙ`/`ΣΤΕΙΛΕ`, κουμπιά συστήματος `VM_*` στο API (§8.1). *Έγινε. Η μικτή οθόνη μετά από εγγραφές στον δίσκο διορθώθηκε μετά το M12 (§7.3, M10).*
14. **M12 — Πράξεις, παράθυρα και κουμπιά στο Studio:** τα blocks 26–33, κείμενα σε πεδία, μορφή `.VBS` 2, προγράμματα σε mode 1, η αριθμομηχανή `CALC` και το `tools/mkvbs.py` (§8.1). Επίσης η αυτόματη επανάληψη του πληκτρολογίου δεν γεμίζει πια την ουρά συμβάντων. *Έγινε.*
15. **M13 — Κοστούμια στο Studio:** επεξεργαστής εικόνων 16×16 στο Studio, blocks `ΚΟΣΤΟΥΜΙ`, `ΕΠΟΜΕΝΟ ΚΟΣΤΟΥΜΙ` και η τιμή `ΚΟΣΤΟΥΜΙ`, μορφή `.VBS` 3, κοστούμια στον παίκτη και στα δύο modes, το παράδειγμα `FLAP` (§8.1). *Έγινε.*
16. **M14 — Relocation και desk accessory:** πίνακας relocation (`tools/mkreloc.py`), ένα δεύτερο πρόγραμμα ως 4K στη bank 6 που ανοίγει με F5 πάνω από κάθε όψη ή πρόγραμμα, API 7, το `CLOCK` (§4.3, §7.3). *Έγινε.*
17. **M15 — Relocation σε όλα τα προγράμματα:** πίνακας σε όσα μπορούν να μετακινηθούν, φόρτωση σε οποιαδήποτε σελίδα της bank, `make test-reloc` (§7.3). *Έγινε.*
18. **M16 — Πολλά προγράμματα μαζί:** θέσεις προγραμμάτων στη bank 5 πάνω από τις όψεις, συνέχιση από τον Launcher με `init` A = 2 (API 8), τα άλλα προγράμματα παγώνουν, `make test-multi` (§7.3). *Έγινε.* Αργότερα ίσως: σημάδι στα πλακίδια, επέκταση μνήμης με μία bank για κάθε πρόγραμμα.

## 12. Αποφάσεις

1. **Interface:** Desktop (A) ως αρχική οθόνη, με Launcher (B) και Commander (C) ως όψεις (§6).
2. **Δισκέτα:** μορφή AMSDOS DATA (§5.2).
3. **Ποντίκι:** AMX Mouse στη θύρα joystick (§3.2), μαζί με cursor keys + COPY.
4. **Editor blocks:** σε PC πρώτα (§8.1).
5. **Γλώσσες:** plugins (language packs), Αγγλικά ενσωματωμένα, πρώτο pack τα Ελληνικά με εμφάνιση και πληκτρολόγηση (§6.6).

# V-OS για Amstrad CPC 6128: τι απαιτείται

Το έγγραφο περιγράφει τι χρειάζεται για ένα πλήρες γραφικό λειτουργικό σύστημα σε Z80 assembly για τον Amstrad CPC 6128, με:

- οθόνη overscan σε mode 0 και mode 1 (και προαιρετικά μικτή),
- απλό σύστημα μενού που χειρίζεται MSX mouse και πληκτρολόγιο (cursor keys, TAB, συντομεύσεις),
- API για προγράμματα που γράφονται σε γλώσσα τύπου Scratch και μεταφράζονται σε assembly,
- δικό του driver δισκέτας για ανάγνωση και εγγραφή προγραμμάτων.

Τα πρότυπα interface βρίσκονται στο `docs/interface-templates.html`.

---

## 1. Υλικό-στόχος

| Στοιχείο | Λεπτομέρειες | Τι σημαίνει για το V-OS |
|---|---|---|
| CPU | Z80A, 4 MHz (πρακτικά ~3,3 MHz λόγω wait states, κάθε εντολή στρογγυλεύεται σε πολλαπλάσιο 4 T-states / 1 µs) | Μετράμε χρόνο σε «NOPs» (µs). Οι ρουτίνες γραφικών πρέπει να είναι ξετυλιγμένες και με lookup tables. |
| RAM | 128K: 64K βασική + 64K επιπλέον σε 4 banks των 16K | Οι επιπλέον banks εμφανίζονται στο παράθυρο `&4000–&7FFF` μέσω της θύρας `&7Fxx` (configurations `&C4–&C7`). |
| Βίντεο | CRTC 6845 + Gate Array, 27 χρώματα hardware | Overscan ρυθμίζεται από τους καταχωρητές του CRTC. Οι αλλαγές mode και παλέτας γίνονται από το Gate Array. |
| CRTC | Τύποι 0, 1, 2 στα 6128 (3/4 στα Plus) | Η συμπεριφορά στο overscan και στα raster tricks διαφέρει ανά τύπο. Πρέπει να δοκιμαστούν όλοι. |
| Ήχος/πληκτρολόγιο | AY-3-8912 μέσω PPI 8255 | Το πληκτρολόγιο και το joystick διαβάζονται μέσω του AY (καταχωρητής 14) και του PPI. |
| Δισκέτα | NEC µPD765A (FDC), εσωτερικός οδηγός 3" + προαιρετικός B: | Χωρίς DMA και χωρίς interrupt: μεταφορά byte-byte με polling, κρίσιμη στο χρόνο. |
| ROM | Lower ROM (firmware), BASIC, AMSDOS | Το V-OS απενεργοποιεί τις ROM και τρέχει μόνο από RAM. Δεν χρησιμοποιεί firmware. |

Ο CPC 6128 Plus (ASIC, hardware sprites, split screen) μπορεί να υποστηριχθεί αργότερα, αλλά ο στόχος είναι ο απλός 6128.

## 2. Οθόνη: overscan, modes, raster split

### 2.1 Overscan

- Ανάλυση: **384×272** σε mode 1 (4 χρώματα), **192×272** σε mode 0 (16 χρώματα). Πλέγμα χαρακτήρων 48×34 και 24×34 αντίστοιχα.
- Μνήμη: 96 bytes ανά γραμμή × 272 = **26.112 bytes**. Η κανονική οθόνη του CPC έχει μόνο 16K, οπότε το overscan απαιτεί **οθόνη 32K** που περνά από το ένα 16K block στο επόμενο (ρύθμιση των bits μεγέθους στον R12 του CRTC).
- Ενδεικτικές τιμές CRTC: `R1=48`, `R2=50`, `R6=34`, `R7=35`, `R12/R13` για οθόνη 32K (π.χ. `R12=&2C, R13=&00` για `&8000–&FFFF`). **Οι ακριβείς τιμές επαληθεύονται σε emulator με επιλογή τύπου CRTC και σε πραγματικό μηχάνημα.**
- Τα περίπου 6,5K που περισσεύουν μέσα στο 32K της οθόνης (κενά στο τέλος των blocks) μπορούν να χρησιμοποιηθούν για buffers.
- Δεν υπάρχει χώρος για double buffering ολόκληρης οθόνης. Χρειάζεται σχεδίαση με dirty rectangles και αποθήκευση του φόντου κάτω από τον δείκτη.

### 2.2 Modes και παλέτα

- Συνάρτηση αλλαγής mode για όλη την οθόνη (mode 0/1) με ταυτόχρονη αλλαγή παλέτας.
- Η κωδικοποίηση pixel διαφέρει ανά mode (στο mode 0 τα bits των 2 pixels είναι πλεγμένα, στο mode 1 των 4 pixels). Χρειάζονται πίνακες μετατροπής (ink → byte mask) για κάθε mode.
- Ξεχωριστά σετ ρουτινών γραφικών ανά mode, με κοινό API (το πρόγραμμα ζητά «ink 3», το σύστημα ξέρει πώς γράφεται).

### 2.3 Μικτή οθόνη (πρότυπο D)

- Ο Gate Array δίνει interrupt κάθε 52 γραμμές HSYNC (6 ανά frame, 300 Hz). Η αλλαγή mode σε συγκεκριμένη γραμμή γίνεται μέσα στο interrupt handler με χρονισμένη αναμονή.
- Ο handler πρέπει να έχει σταθερή διάρκεια, να αλλάζει mode και παλέτα στις ζώνες, και να μην χάνει τον συγχρονισμό όταν τρέχει κώδικας δισκέτας (βλ. §5.4).
- Οι αλλαγές γίνονται στην αρχή της γραμμής. Ό,τι σχεδιάζεται σε μια ζώνη ακολουθεί το mode εκείνης της ζώνης, άρα και τα μενού που «πέφτουν» στη ζώνη mode 0.

### 2.4 Βιβλιοθήκη γραφικών

- Βασικά: plot, οριζόντια/κάθετη γραμμή, γραμμή Bresenham, γέμισμα ορθογωνίου, πλαίσιο, dither patterns.
- Blit: αντιγραφή ορθογωνίου, sprites με μάσκα (save/restore background), εικονίδια 16×16 / 24×16.
- Κείμενο: γραμματοσειρά 8×8 (ASCII + ελληνικά). Στο mode 0 προαιρετική στενή γραμματοσειρά 4×8 για περισσότερες στήλες.
- Clipping σε ορθογώνιο (απαραίτητο για παράθυρα και μενού).
- Υπολογισμός διεύθυνσης γραμμής με πίνακα 272 εγγραφών (2 bytes η καθεμία, ~544 bytes) αντί για υπολογισμό κάθε φορά.

## 3. Είσοδος

### 3.1 Πληκτρολόγιο

- Σάρωση του πίνακα 10×8 μέσω PPI/AY, μία φορά ανά frame (ή στα 300 Hz για καλύτερη απόκριση).
- Debounce, auto-repeat με ρυθμιζόμενη καθυστέρηση, ουρά συμβάντων (key down / key up / χαρακτήρας).
- Keymap: λατινικά και ελληνικά (εναλλαγή με συνδυασμό πλήκτρων), modifiers SHIFT, CONTROL, COPY.
- Χάρτης πλοήγησης UI: cursor keys, TAB / SHIFT+TAB, RETURN/ENTER, ESC, COPY ως «άνοιγμα μενού», CONTROL+γράμμα ή σκέτο γράμμα για συντομεύσεις μενού.

### 3.2 MSX mouse

- Το MSX mouse στέλνει τις μετακινήσεις X/Y σε τέσσερα nibbles, με εναλλαγή σήματος strobe ανάμεσα στις αναγνώσεις.
- **Κρίσιμο ρίσκο υλικού:** η θύρα joystick του CPC δεν έχει ελεύθερη γραμμή εξόδου για το strobe όπως το MSX. Υπάρχουν λύσεις με adapter ή με εκμετάλλευση των γραμμών common της θύρας κατά τη σάρωση του πληκτρολογίου. Πρέπει να επιλεγεί και να δοκιμαστεί η συγκεκριμένη συνδεσμολογία νωρίς, σε πραγματικό υλικό.
- Ο driver πρέπει να είναι αφηρημένος: μια διεπαφή `mouse_read → dx, dy, buttons` με υλοποιήσεις για MSX mouse, AMX mouse, κάρτες τύπου Multiplay και «ψεύτικο» ποντίκι από joystick ή cursor keys.
- Επιτάχυνση, όρια οθόνης, ταχύτητα ρυθμιζόμενη από το Setup.
- Δείκτης λογισμικού: σχεδιάζεται τελευταίος σε κάθε ανανέωση με save-under, σε δύο εκδοχές (mode 0 και mode 1).

### 3.3 Μοντέλο εστίασης και πλοήγησης

- Κάθε στοιχείο UI (κουμπί, εικονίδιο, γραμμή λίστας, μενού) έχει: ορθογώνιο, σειρά TAB, προαιρετικό πλήκτρο συντόμευσης, handler.
- Ποντίκι και πληκτρολόγιο παράγουν τα ίδια συμβάντα (`FOCUS`, `ACTIVATE`, `MENU_OPEN`, `MENU_SELECT`), ώστε οι εφαρμογές να μη χρειάζεται να ξεχωρίζουν από πού ήρθε η εντολή.
- Μενού: γραμμή μενού, πτυσσόμενα μενού, διαχωριστικά, απενεργοποιημένα στοιχεία, εμφάνιση συντόμευσης δεξιά.

## 4. Πυρήνας (kernel)

### 4.1 Εκκίνηση

- Φάση 1: φόρτωση από BASIC με `RUN"VOS"` (απλό, συμβατό με κάθε δισκέτα DATA).
- Φάση 2: δισκέτα εκκίνησης τύπου SYSTEM με `|CPM` που φορτώνει boot sector από track 0, ώστε το V-OS να μην εξαρτάται καθόλου από AMSDOS.
- Μετά τη φόρτωση: απενεργοποίηση ROM, εγκατάσταση δικού του interrupt handler (IM 1 στο `&0038`), αρχικοποίηση CRTC, παλέτας, πληκτρολογίου, FDC.

### 4.2 Χάρτης μνήμης (πρόταση, προς οριστικοποίηση)

| Περιοχή | Περιεχόμενο |
|---|---|
| `&0000–&00FF` | Restart vectors, interrupt handler, πίνακας κλήσεων API |
| `&0100–&3FFF` | Kernel: drivers, γραφικά, UI, filesystem (~16K) |
| `&4000–&7FFF` | Παράθυρο bank: εφαρμογή χρήστη ή δεδομένα της (banks `&C4–&C7`, 4×16K) |
| `&8000–&FFFF` | Οθόνη overscan 32K (26K χρήσιμα + buffers στα κενά) |

Το βασικό ζήτημα είναι ότι η οθόνη των 32K αφήνει μόνο 32K στη βασική μνήμη. Εναλλακτικές:
- εφαρμογές μέχρι 16K ανά bank, με κλήσεις kernel από το παράθυρο `&4000`,
- μέρος του kernel (π.χ. filesystem, γραμματοσειρές) σε bank που εναλλάσσεται όταν χρειάζεται,
- χρήση των configurations `&C1`/`&C2`/`&C3` για μεγαλύτερες εφαρμογές.

### 4.3 Υπηρεσίες

- **Βρόχος συμβάντων**: ουρά (πλήκτρα, ποντίκι, timer, δίσκος, μηνύματα), dispatch στην ενεργή εφαρμογή.
- **Χρονόμετρα**: μετρητής frames (50 Hz) και ticks (300 Hz), ρολόι ώρας λογισμικού, `wait`.
- **Διαχείριση μνήμης**: δέσμευση/απελευθέρωση banks και μπλοκ μέσα σε αυτά, σωρός για το UI.
- **Loader**: φόρτωση εφαρμογής από δισκέτα, έλεγχος header, relocation, κλήση των σημείων εισόδου.
- **Πολυεργασία**: συνεργατική (cooperative). Μία εφαρμογή τη φορά συν μικρά «desk accessories» (ρολόι, σημειώσεις) που τρέχουν στο ίδιο event loop. Όχι preemptive.
- **Χειρισμός σφαλμάτων**: παράθυρο σφάλματος συστήματος, επιστροφή στο shell χωρίς επανεκκίνηση όπου είναι εφικτό.
- **Ήχος**: απλός driver AY (beep, νότα, ένταση, σίγαση) που τρέχει στο interrupt.

## 5. Driver δισκέτας και σύστημα αρχείων

### 5.1 Χαμηλό επίπεδο (FDC µPD765)

- Θύρες: `&FB7E` (status), `&FB7F` (data), `&FA7E` (motor on/off).
- Εντολές: Specify, Recalibrate, Seek, Sense Interrupt Status, Read ID, Read Data, Write Data, Format Track, Sense Drive Status.
- Μεταφορά δεδομένων με polling του status register. Ο βρόχος πρέπει να είναι αρκετά γρήγορος ώστε να μη χάνεται byte (overrun). Κατά τη μεταφορά τα interrupts απενεργοποιούνται ή ο handler συντομεύει.
- Διαχείριση μοτέρ: εκκίνηση με αναμονή ~1 s, αυτόματο σβήσιμο μετά από αδράνεια.
- Επαναλήψεις και αναφορά σφαλμάτων (no ID, CRC, write protect, not ready) σε κατανοητά μηνύματα.
- Δύο μονάδες (A:, B:), 40 tracks στα 3", προαιρετικά 80 tracks για εξωτερικό 3,5".

### 5.2 Μορφή δισκέτας

**Πρόταση:** συμβατότητα με τη μορφή **AMSDOS DATA** (40 tracks, 9 sectors × 512 bytes, IDs `&C1–&C9`, 178K, 64 εγγραφές καταλόγου, blocks 1K, κατάλογος τύπου CP/M 2.2).

Πλεονεκτήματα: τα αρχεία του V-OS διαβάζονται από BASIC, emulators και εργαλεία (`iDSK`, RASM), και αντίστροφα. Το V-OS χρησιμοποιεί το header των 128 bytes του AMSDOS για να σημειώνει τον τύπο του αρχείου.

Εναλλακτικά, δικό του filesystem (π.χ. μεγαλύτερα ονόματα, φάκελοι), με κόστος την ασυμβατότητα. Μπορεί να προστεθεί αργότερα ως δεύτερη μορφή.

### 5.3 Υψηλό επίπεδο

- Κατάλογος (catalog), open/read/write/close, διαγραφή, μετονομασία, ελεύθερος χώρος, format, αντιγραφή δισκέτας.
- Buffer ενός sector ή ενός track (4,5K) για ταχύτητα.
- Τύποι αρχείων V-OS: `.BIN` (εφαρμογή), `.VBP` (project blocks), `.SCR` (εικόνα), `.SND`, `.FNT`, `.DRV`, `.CFG`.

### 5.4 Αλληλεπίδραση με την οθόνη

Αν ενεργοποιηθεί η μικτή οθόνη (πρότυπο D), οι προσβάσεις στη δισκέτα με κλειστά interrupts σπάνε το raster split. Κατά την ανάγνωση και εγγραφή η οθόνη επιστρέφει προσωρινά σε ενιαίο mode ή ο driver σχεδιάζεται να κάνει τη μεταφορά ανάμεσα στα interrupts.

## 6. Περιβάλλον χρήστη (shell)

**Απόφαση:** ένα shell με τρεις όψεις. Το Desktop (A) είναι η αρχική οθόνη, ο Launcher (B) και ο Commander (C) είναι εναλλακτικές όψεις.

### 6.1 Οι τρεις όψεις

| Όψη | Mode | Ρόλος | Πώς ανοίγει |
|---|---|---|---|
| A · Desktop | 1 | Αρχική οθόνη: γραμμή μενού, παράθυρα, εικονίδια δίσκων, εφαρμογές σε παράθυρα | Προεπιλογή εκκίνησης, `1`, μενού Launcher → Desktop, Commander → Options |
| B · Launcher | 0 | Πλέγμα 3×3 πλακιδίων για γρήγορη εκκίνηση, φιλικό σε παιδιά και joystick | `2`, μενού View (A) ή Options (C) |
| C · Commander | 1 | Δύο πάνελ A:/B:, αντιγραφή, format, μαζικές ενέργειες σε αρχεία | `3`, μενού View (A) ή Sys (B) |

Στο πραγματικό μηχάνημα οι συντομεύσεις `1/2/3` μπορούν να είναι τα πλήκτρα f1/f2/f3 του αριθμητικού πληκτρολογίου, ώστε να μη συγκρούονται με την πληκτρολόγηση.

### 6.2 Τι μοιράζονται

- **Μηχανή μενού και εστίασης** (§3.3): κάθε όψη δηλώνει μόνο τα μενού και τα στοιχεία της. Η πλοήγηση, το ποντίκι και οι συντομεύσεις είναι κοινός κώδικας.
- **Κατάλογος εφαρμογών**: όνομα, τύπος, εικονίδιο σε δύο εκδοχές (mode 1 για το A, mode 0 για το B), θέση στη δισκέτα. Το C δείχνει τα ίδια αρχεία ως λίστα.
- **Κατάσταση συστήματος**: επιλεγμένη μονάδα, επιλεγμένο αρχείο, πρόχειρο αντιγραφής. Η εναλλαγή όψης κρατά την επιλογή.
- **Ρυθμίσεις**: ποια όψη ανοίγει στην εκκίνηση (π.χ. B για παιδικό προφίλ), αποθηκευμένη στο `SETUP.CFG`.

### 6.3 Εναλλαγή όψης

1. Κλείσιμο ανοιχτού μενού, αποθήκευση της κατάστασης της τρέχουσας όψης.
2. Αναμονή για VSYNC, αλλαγή mode και παλέτας από τον Gate Array, καθάρισμα οθόνης.
3. Πλήρης σχεδίαση της νέας όψης και επαναφορά του δείκτη στη μορφή του νέου mode.

Κάθε όψη έχει δική της παλέτα 4 ή 16 inks. Για συνέπεια, το A και το C μοιράζονται βασικά χρώματα (μπλε φόντο, λευκό κείμενο) και διαφέρουν μόνο στα χρώματα έμφασης.

### 6.4 Μνήμη

Οι τρεις όψεις δεν χωρούν μαζί στα ~16K του kernel. Η πρόταση είναι κάθε όψη να είναι **overlay** σε δική της bank των 16K (ή να φορτώνεται από τη δισκέτα), και ο kernel να κρατά μόνο τον κοινό κώδικα: μενού, εστίαση, γραφικά, αρχεία. Ο Launcher χρειάζεται επιπλέον τις ρουτίνες κειμένου και blit για mode 0.

### 6.5 Λοιπά

- Διαχείριση αρχείων: περιήγηση A:/B:, εκτέλεση, αντιγραφή, διαγραφή, μετονομασία, πληροφορίες (στο A ως παράθυρα, στο C ως πάνελ).
- Ρυθμίσεις (Setup): ποντίκι, ταχύτητα επανάληψης πλήκτρων, χρώματα, προτιμώμενο mode, γλώσσα, αποθήκευση σε `SETUP.CFG`.
- Διάλογοι συστήματος: μήνυμα, επιβεβαίωση, επιλογή αρχείου, εισαγωγή κειμένου.
- Ελληνικά: γραμματοσειρά με ελληνικούς χαρακτήρες (κεφαλαία και πεζά), κωδικοσελίδα (π.χ. υποσύνολο ISO 8859-7 στις θέσεις 128–255).

## 7. API για εφαρμογές

### 7.1 Μηχανισμός κλήσης

- Σταθερός πίνακας άλματος (jump table) σε γνωστή διεύθυνση, π.χ. `CALL &0103 + 3*n`, ή `RST &28` ακολουθούμενο από έναν byte αριθμό συνάρτησης (μικρότερος κώδικας, λίγο πιο αργό).
- Συμβάσεις καταχωρητών: παράμετροι σε `A, BC, DE, HL`, επιστροφή σε `A`/`HL`, σφάλμα στο Carry flag. Τεκμηριωμένο ποιοι καταχωρητές καταστρέφονται.
- Αριθμός έκδοσης API, ώστε οι εφαρμογές να ελέγχουν τη συμβατότητα.

### 7.2 Ομάδες συναρτήσεων (ενδεικτικά)

| Ομάδα | Συναρτήσεις |
|---|---|
| `SYS` | version, exit, yield, get_ticks, wait_frames, random |
| `MEM` | alloc_bank, free_bank, alloc, free |
| `GFX` | set_mode, set_ink, cls, plot, line, rect, fill_rect, blit, sprite_draw, sprite_erase, set_clip |
| `TXT` | print_at, print_char, set_font, text_width |
| `UI` | menu_define, menu_bar, dialog_msg, dialog_confirm, dialog_file, button, list |
| `INP` | key_pressed, key_get, mouse_get, joy_get, wait_event |
| `FILE` | catalog, open, read, write, close, delete, rename, free_space |
| `SND` | beep, note, volume, silence |

### 7.3 Μορφή εφαρμογής (`.BIN` του V-OS)

Header με:
- magic `VOS`, έκδοση API, ζητούμενο mode (0, 1, μικτό),
- μέγεθος κώδικα και δεδομένων, πίνακα relocation,
- σημεία εισόδου: `init`, `event`, `draw`, `exit`,
- όνομα (έως 8 χαρακτήρες) και εικονίδιο 16×16 για το shell.

## 8. Γλώσσα τύπου Scratch και μεταγλωττιστής

### 8.1 Πού τρέχει ο editor

- **Φάση 1 (προτείνεται):** editor σε PC (web, π.χ. με Blockly) που παράγει Z80 assembly, το οποίο μεταγλωττίζεται με RASM ή sjasmplus και γράφεται σε εικόνα `.DSK`. Γρήγορη ανάπτυξη και εύκολος έλεγχος του παραγόμενου κώδικα.
- **Φάση 2:** native editor μέσα στο V-OS (πρότυπο D, «Studio»), που αποθηκεύει `.VBP` και μεταγλωττίζει επί τόπου σε `.BIN`. Πολύ πιο απαιτητικό σε μνήμη και χρόνο ανάπτυξης.

### 8.2 Γλώσσα

- Κατηγορίες blocks: κίνηση, εμφάνιση, ήχος, συμβάντα, έλεγχος, αισθητήρες, τελεστές, μεταβλητές.
- Τύποι: ακέραιοι 8 και 16 bit, boolean, σταθερά strings, λίστες σταθερού μεγέθους. Χωρίς floating point στην πρώτη έκδοση.
- Συμβάντα: `when start`, `when key`, `when click`, `when receive`, `broadcast`.
- Sprites: θέση, κατεύθυνση, κοστούμια, σύγκρουση με ορθογώνια.

### 8.3 Παραγωγή κώδικα

- Κάθε block αντιστοιχεί σε ένα πρότυπο assembly που καλεί το API ή μια μικρή runtime library.
- Πολλαπλά scripts (`forever`, παράλληλα events) υλοποιούνται ως **coroutines**: κάθε script έχει δική του στοίβα ή κατάσταση και κάνει `yield` στο τέλος κάθε επανάληψης. Αυτό δίνει τη συμπεριφορά του Scratch χωρίς preemptive multitasking.
- Απλή ανάθεση καταχωρητών, με μεταβλητές σε σταθερές θέσεις μνήμης. Βελτιστοποιήσεις (constant folding, peephole) αργότερα.
- Έξοδος: αρχείο `.ASM` (για διάβασμα και εκμάθηση) και `.BIN` με το header του V-OS.

## 9. Εργαλεία ανάπτυξης και δοκιμές

- **Assembler:** RASM (γράφει απευθείας σε `.DSK`, υποστηρίζει banks του CPC) ή sjasmplus.
- **Emulators:** ACE-DL ή CPCEC (επιλογή τύπου CRTC, ακριβής χρονισμός), WinAPE (debugger), Retro Virtual Machine.
- **Εικόνες δισκέτας:** `iDSK` ή RASM για δημιουργία και επεξεργασία `.DSK`.
- **Build:** Makefile που μεταγλωττίζει kernel, εφαρμογές και δημιουργεί `VOS.DSK`.
- **Δοκιμές:** σε όλους τους τύπους CRTC (0, 1, 2) στον emulator, σε πραγματικό 6128 με 3" και με Gotek/HxC, και ειδικά για τη συνδεσμολογία του MSX mouse.
- **Repo:** `src/kernel`, `src/drivers` (fdc, kbd, mouse, crtc), `src/gfx`, `src/ui`, `src/apps`, `compiler/`, `docs/`, `tools/`.

## 11. Προτεινόμενα ορόσημα

1. **M0 — Υποδομή:** repo, Makefile, RASM, εκκίνηση από `RUN"VOS"`, απενεργοποίηση ROM, δικός interrupt handler.
2. **M1 — Οθόνη:** overscan σε mode 1 και mode 0, παλέτα, plot/rect/text, ελληνική γραμματοσειρά.
3. **M2 — Είσοδος:** πληκτρολόγιο με ουρά συμβάντων, δείκτης ποντικιού από cursor keys, μετά MSX mouse.
4. **M3 — UI:** γραμμή μενού, πτυσσόμενα μενού, εστίαση και TAB, διάλογοι.
5. **M4 — Δισκέτα:** driver FDC (read sector), μετά write και format, filesystem συμβατό με AMSDOS.
6. **M5 — Shell:** πρώτα το Commander (C, μόνο κείμενο, γρηγορότερο να γίνει), μετά το Desktop (A) με παράθυρα, τέλος ο Launcher (B) σε mode 0. Εναλλαγή όψεων και Setup.
7. **M6 — API και loader:** jump table, header εφαρμογών, banks, πρώτη εφαρμογή-δείγμα.
8. **M7 — Cross-compiler:** web editor blocks → ASM → `.BIN` σε `.DSK`.
9. **M8 — Studio:** μικτή οθόνη και native editor (προαιρετικό).

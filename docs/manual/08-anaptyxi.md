# 8. Ανάπτυξη του V-OS

Για όσους δουλεύουν στο ίδιο το V-OS. Τα προγράμματα *για* το V-OS περιγράφονται στο [SDK](../../sdk/README.md).

## Τι χρειάζεται

- [RASM](https://github.com/EdouardBERGE/rasm), ο assembler
- [iDSK](https://github.com/cpcsdk/idsk), για τις εικόνες δισκέτας
- Python 3, για τα εργαλεία. Για το `make docs` χρειάζεται και τα `markdown` και `pymupdf`.
- GNU make 4.3 ή νεότερο
- για δοκιμές, ο Caprice32 (snap `caprice32`)

## Build

| Εντολή | Τι κάνει |
|---|---|
| `make` | `build/vos.dsk`: ο kernel, οι όψεις, οι γλώσσες, όλα τα προγράμματα και τα `myapps/*` |
| `make run` | ανοίγει τη δισκέτα στον Caprice32 (`RUN"VOS"`) |
| `make shot` | εκκίνηση χωρίς παράθυρο και ένα screenshot |
| `make docs` | το manual ως PDF: `docs/V-OS.pdf` (ελληνικά) και `docs/V-OS-en.pdf`, `-fr`, `-es`, `-de`, `-it` |
| `make new-app NAME=x`, `make app NAME=x` | δικό σου πρόγραμμα (SDK) |
| `make clean` | σβήνει το `build/` |

## Η μνήμη, σε συντομία

| Περιοχή | Τι έχει |
|---|---|
| `#0000–#3DFF` | ο kernel. Στη σελίδα μηδέν, μετά τα restart vectors, ο πίνακας του API στο `#0108` |
| ως `#4000` | η στοίβα του kernel |
| `#4000–#7FFF` | το «παράθυρο» των banks |
| `#8000–#FFFF` | η οθόνη overscan 32K. Στα κενά της, buffers του kernel |

Οι banks που μπαίνουν στο παράθυρο:

| Bank | Τι έχει |
|---|---|
| 4 | buffer αρχείων και φόρτωσης, και η bank δεδομένων του προγράμματος που τρέχει |
| 5 | η όψη στο `#4000–#4FFF`, και από το `#5000` τα προγράμματα με πίνακα relocation (ή ένα πρόγραμμα χωρίς πίνακα σε όλη τη bank) |
| 6 | ό,τι κρύβουν τα μενού και οι διάλογοι, και από το `#7000` το desk accessory |
| 7 | το language pack, οι λίστες του Commander, τα αγγλικά κείμενα, και από το `#7000` το kernel extension |

Με επέκταση μνήμης, οι banks της παίρνουν προγράμματα. Οι λεπτομέρειες, διεύθυνση προς διεύθυνση, είναι στο `docs/REQUIREMENTS.md` (§4.2 και σε κάθε «Υλοποίηση M…»).

## Συμβάσεις

- **RASM:** τα hex γράφονται `#C000` και όχι `&C000`, γιατί η RASM διαβάζει το `&` ως AND. Οι ετικέτες δεν ξεχωρίζουν κεφαλαία από πεζά.
- **Σχόλια:** στα αγγλικά, σύντομα, όπως στον υπάρχοντα κώδικα. Κάθε αρχείο ξεκινά με ένα μπλοκ που λέει τι κάνει.
- **Τεκμηρίωση:** στα ελληνικά. Το `README.md` και το `docs/REQUIREMENTS.md` έχουν μια ενότητα για κάθε milestone. Το manual γράφεται στα ελληνικά και μεταφράζεται στις άλλες πέντε γλώσσες του V-OS.
- **Κείμενα:** τα κείμενα του συστήματος είναι στο `lang/*/messages.txt`, και των προγραμμάτων σε `texts.txt` (για το `tools/mktexts.py`).

## Δοκιμές

Οι δοκιμές τρέχουν το V-OS στον Caprice32 χωρίς παράθυρο και τραβούν screenshots στο `build/shots/<καθυστέρηση>/`.

**Πώς δουλεύουν:**

- Ο Caprice32 χωρίς παράθυρο δεν μπορεί να πατήσει βελάκια, COPY ή πλήκτρα f. Γι' αυτό τα πατήματα τα κάνει ένα ειδικό build: ένα `-DTEST_SCRIPT=n` βάζει στο `src/kernel/test_script.asm` το σενάριο n, έναν πίνακα με πλήκτρα ανά frame.
- Κάθε στόχος `make test-…` χτίζει μια δισκέτα με το σενάριό του και τραβά ένα screenshot σε κάθε καθυστέρηση του `…_SHOTS`.
- Η καθυστέρηση μετριέται σε πατήματα «Z»: περίπου 2,5–3,5 frames το καθένα. Η αντιστοιχία δεν είναι σταθερή, οπότε ένα στιγμιότυπο το πιάνεις με δύο-τρεις καθυστερήσεις γύρω του.
- Αφού το V-OS γράψει στη δισκέτα, ο Caprice32 δεν κλείνει μόνος του, και η δοκιμή τελειώνει με timeout. Είναι αναμενόμενο σε test-vars, test-costume κ.ά.
- Τα screenshots τα κοιτάζεις, π.χ. συνδυασμένα σε μία εικόνα με `ffmpeg … hstack/vstack`.

| Στόχος | Τι δοκιμάζει |
|---|---|
| `test-input` | πλήκτρα, Studio: blocks, αρχεία, εκτέλεση |
| `test-calc` | η CALC με κλικ, μετά το `CALC.VBS` στο Studio |
| `test-costume` | κοστούμι στο Studio, εκτέλεση, ξανά άνοιγμα |
| `test-acc` | το ρολόι ως desk accessory |
| `test-multi`, `test-switch`, `test-expand`, `test-behind` | πολλά προγράμματα, F6, επέκταση μνήμης, παρασκήνιο |
| `test-drag` | σύρσιμο παραθύρων |
| `test-langs`, `test-lang` | οι γλώσσες, η αποθήκευση της γλώσσας |
| `test-mines`, `test-bricks` | τα παιχνίδια |
| `test-vars` | οι 128 μεταβλητές, SAVE/LOAD VARS |
| `test-sdk` | το πρότυπο του SDK |
| `test-vrouves` | το VROUVES: χτίσιμο, το κύμα 1, τα λεφτά |
| `test-amsdos`, `test-reboot`, `test-system` | τα αρχεία του V-OS στη BASIC, επανεκκίνηση, δισκέτα SYSTEM |

**Νέο σενάριο:**

1. Πρόσθεσε ένα `IF TEST_SCRIPT == n` στην αρχή της αλυσίδας του `test_script.asm`, με `ELSE` πριν από το επόμενο και ένα ακόμα `ENDIF` στο τέλος.
2. Πρόσθεσε έναν στόχο στο Makefile, όπως το `test-sdk`.

Κάθε πλήκτρο γράφεται ως `dw από, ως : db γραμμή, bit` του πληκτρολογίου. Ο αριθμός του πλήκτρου είναι γραμμή·8 + bit, π.χ. RETURN = 18 = γραμμή 2, bit 2.

**Χωρίς εξομοιωτή:** κώδικας ενός προγράμματος τρέχει και σε Z80 μέσα στην Python (πακέτο `z80`). Φορτώνεις το `.BIN` στο `#4000` και βάζεις τις κλήσεις του API να επιστρέφουν αμέσως (ή να κάνουν ό,τι χρειάζεται, π.χ. αρχεία σε λεξικό). Τότε καλείς το init και το event και διαβάζεις τη μνήμη. Είναι πολύ γρηγορότερο από τα screenshots για λάθη σε αριθμούς, αρχεία και άλματα. Τις διευθύνσεις των labels τις δίνει το `rasm … -s -sl` (αρχείο `.sym`).

## Κάθε milestone

1. Κώδικας, και δοκιμή στον Caprice32: νέα ή υπάρχουσα, με screenshots.
2. Οι δοκιμές που αγγίζει η αλλαγή.
3. Ενότητα στο `README.md` και «Υλοποίηση M…» στο `docs/REQUIREMENTS.md`.
4. **Ενημέρωση του manual και στις έξι γλώσσες** (`docs/manual/` στα ελληνικά, `docs/manual/<κωδικός>/` για en, fr, es, de, it, και τα `sdk/README.md`, `sdk/README.<κωδικός>.md` αν αλλάζει το API), και `make docs` για όλα τα PDF.
5. Commit και push.

# SDK του V-OS: προγράμματα σε assembly

Με αυτό το SDK γράφεις δικά σου προγράμματα σε Z80 assembly. Τρέχουν μέσα στο V-OS όπως το DEMO ή το CLOCK: εμφανίζονται στον Launcher, το Desktop και τον Commander, και έχουν δικό τους μενού, κουμπιά, διαλόγους, ήχο και αρχεία. Τρέχουν και δίπλα σε άλλα προγράμματα.

## Γρήγορο ξεκίνημα

```bash
make new-app NAME=hello
```

Αυτό φτιάχνει τον φάκελο `myapps/hello/` από το `sdk/template/`. Έχει τρία αρχεία:

- `hello.asm`: το πρόγραμμα. Τα βέλη κινούν ένα κουτί, υπάρχει ένα κουμπί ΗΧΟΣ, ένας μετρητής δευτερολέπτων, και ένα δικό του μενού (ABOUT, BACK) δίπλα στα VIEW και HELP.
- `texts.txt`: τα κείμενά του, σε αγγλικά και ελληνικά.
- `icon.txt`: το εικονίδιό του, 16×16, για τον Launcher.

```bash
make app NAME=hello
```

Αυτό χτίζει το `build/HELLO.BIN` και το βάζει στη δισκέτα `build/vos.dsk`.

```bash
make run
```

Αυτό ανοίγει τη δισκέτα στον Caprice32. Το HELLO είναι στον Launcher, στην τελευταία σελίδα.

- Το απλό `make` χτίζει και βάζει στη δισκέτα όλα τα προγράμματα του `myapps/`, μαζί με το V-OS.
- Το όνομα έχει 1–8 πεζά γράμματα ή ψηφία και ξεκινά με γράμμα. Δεν μπορεί να είναι όνομα προγράμματος του V-OS (π.χ. demo).
- Χρειάζεσαι τη RASM, Python 3 και το iDSK, όπως για όλο το V-OS.
- Στον Caprice32 το πρόγραμμα το τρέχεις εσύ, από τον Launcher.

Μεγαλύτερο πρόγραμμα:

- Βάλε κι άλλα `.asm` στον φάκελό του (π.χ. `art.asm` με sprites) και φέρε τα με `include "art.asm"`. Το build τα βρίσκει, και ξαναχτίζει το πρόγραμμα όταν αλλάζουν.
- Ό,τι βάλεις στον υποφάκελο `disc/` (π.χ. `disc/LEVEL1.DAT`) μπαίνει ως έχει στη δισκέτα, για το `VOS_LOAD`.
- Με υποφάκελο `owndisc/`, το πρόγραμμα παίρνει και δική του δισκέτα, `build/<όνομα>.dsk`, με το `.BIN` και τα αρχεία του `owndisc/`. Δεν μπαίνει στη `vos.dsk`. Τη βάζεις στο B: και το τρέχεις από τον Launcher (TAB, η άλλη μονάδα). Από ποιον οδηγό ξεκίνησε, για να φορτώσει τα αρχεία του από εκεί, το λέει το `VOS_SELF`: `db οδηγός`, και μετά το όνομά του (11 bytes).
- **Αρχείο για άνοιγμα (έκδοση 14):** όταν το RETURN στο Desktop ή στον Commander ανοίγει ένα αρχείο στο πρόγραμμά σου, το `VOS_OPEN` (`#B000`) έχει `db 1, οδηγός, όνομα 11 bytes` (0: κανένα). Διάβασέ το στο `init`, με A = 0 και με A = 2 (το πρόγραμμα έτρεχε ήδη), και γράψε μετά 0 εκεί. Οι τύποι και τα προγράμματά τους είναι στον πίνακα `ft_open` του kernel (`src/kernel/files_ext.asm`).
- Ένα πρόγραμμα με πίνακα relocation (όπως αυτά του SDK) χωράει ως 12K. Για τα υπόλοιπα, φόρτωσε αρχεία στη bank δεδομένων.

## Πώς δουλεύει ένα πρόγραμμα

Ένα πρόγραμμα είναι ένα `.BIN`, χτισμένο για το `VOS_APP_ADDR` (`#4000`). Ξεκινά έτσι:

```
        include "api/vos_api.inc"
        org VOS_APP_ADDR
        jp init                 ; +0
        jp event                ; +3  HL -> το γεγονός
        jp redraw               ; +6
        db "VA", VOS_API_VERSION
        include "app_icon.asm"  ; +12 το εικονίδιο (προαιρετικό)
```

- **`init`** ορίζει mode, παλέτα, μενού και κουμπιά, ανοίγει τα `VE_FRAME` αν χρειάζεται, και σχεδιάζει τα πάντα.
  - A = 0: νέα εκκίνηση.
  - A = 2: το πρόγραμμα επιστρέφει από μια όψη ή άλλο πρόγραμμα. Η κατάστασή του είναι όπως την άφησε· ορίζει ξανά τα παραπάνω και σχεδιάζει.
- **`event`** καλείται για κάθε γεγονός και επιστρέφει αμέσως. Ένα πρόγραμμα δεν περιμένει ποτέ μόνο του (κανένας βρόχος αναμονής). Για κίνηση ή χρόνο, `VOS_TICKS` με A = 1, και τότε έρχεται ένα `VE_FRAME` 50 φορές το δευτερόλεπτο.
- **`redraw`** ξανασχεδιάζει τα πάντα, π.χ. όταν αλλάζει η γλώσσα ή κλείνει το desk accessory.
- **Έξοδος:** `VOS_EXIT`, που επιστρέφει στην όψη που το ξεκίνησε.

### Η σειρά μέσα στο `event`

```
event:  ld a,(hl)
        cp VE_FRAME : jp z,frame        ; τα frames
        push hl
        call VOS_UI_EVENT               ; μενού, κουμπιά, CONTROL+γράμμα
        pop hl
        or a : jr nz,command            ; A = η εντολή
        call VOS_MENU_OPEN : ret nz     ; ανοιχτό μενού: τα πλήκτρα είναι δικά του
        ...                             ; τα δικά σου πλήκτρα και κλικ
command: ...
        jp VOS_COMMAND                  ; ό,τι δεν είναι δικό σου (VIEW, HELP)
```

**Όσο είναι ανοιχτό μενού, μη σχεδιάζεις.** Αλλιώς θα γράψεις πάνω του. Στο `VE_FRAME`, ενημέρωσε την κατάσταση, αλλά σχεδίασε μόνο αν το `VOS_MENU_OPEN` δίνει Z. Οι διάλογοι (`VOS_DIALOG`, `VOS_INPUT`, `VOS_FILE_PICK`) έχουν δικό τους βρόχο, οπότε δεν έρχεται κανένα γεγονός όσο είναι ανοιχτοί.

### Τα γεγονότα

`HL` → 8 bytes: `db type, code, char, mods; dw x, y`.

| type | τι | code / char / x, y |
|---|---|---|
| `VE_KEY_DOWN` 1, `VE_KEY_REPEAT` 3, `VE_KEY_UP` 2 | πλήκτρο | code = αριθμός πλήκτρου (`VK_*`, γραμμή·8 + bit του πληκτρολογίου), char = ο χαρακτήρας στη γλώσσα του pack |
| `VE_PTR_DOWN` 5, `VE_PTR_UP` 6, `VE_PTR_MOVE` 4 | δείκτης | x, y σε pixels του mode |
| `VE_FRAME` 8 | frame (με `VOS_TICKS`) | — |
| `VE_LANG` 7 | άλλαξε η γλώσσα του πληκτρολογίου | — |

### Τρία είδη προγράμματος

- **Με πίνακα relocation (το προεπιλεγμένο του SDK):** το `make app` το χτίζει δύο φορές, στο `#4000` και στο `#4100`. Το `tools/mkreloc.py` προσθέτει τον πίνακα από τη διαφορά.
  - Τρέχει δίπλα σε άλλα προγράμματα, στα 12K από το `#5000`, και συνεχίζει όπου σταμάτησε (με F6 φαίνονται τα προγράμματα που τρέχουν).
  - Τα δεδομένα του πρέπει να είναι μέσα στα δικά του bytes (labels, `ds`), ποτέ σε σταθερές διευθύνσεις.
  - Αν το `mkreloc.py` βγάλει σφάλμα, κάπου χρησιμοποιείται διεύθυνση με τρόπο που δεν αντέχει μετακίνηση. Π.χ. `ld a,label & 255`, ή μόνο το low byte μιας διεύθυνσης.
- **Χωρίς πίνακα:** παίρνει όλη τη bank (ως 16K, κώδικας και δεδομένα), αλλά τρέχει μόνο του, εκτός αν υπάρχει επέκταση μνήμης. Για αυτό χρειάζεται δικός σου κανόνας στο Makefile (βλ. `STUDIO.BIN`).
- **Desk accessory:** ως 4K, με πίνακα. Ανοίγει με F5 πάνω από οτιδήποτε, και το `init` παίρνει A = 1. Βλ. `apps/clock/clock.asm` και την περιγραφή στο `src/api/vos_api.inc`.

### Κανόνες

- **Καταχωρητές:** οι κλήσεις χαλάνε όλους τους καταχωρητές εκτός από το IX. Τα ορίσματα μπαίνουν σε A, BC, DE, HL (IX για `VOS_RECT` και `VOS_BLIT`). Τα αποτελέσματα επιστρέφουν σε A ή HL. Σε αποτυχία γυρίζει carry και A = αριθμός σφάλματος, που τον δείχνει το `VOS_ERROR`.
- **Μνήμη:** μην απλώνεις άλλη bank στο `#4000`, γιατί το πρόγραμμα θα εξαφανιστεί από κάτω σου. Για 16K επιπλέον υπάρχει η bank δεδομένων (`VOS_BANK_GET`, `VOS_BANK_PUT`, `VOS_DATA`). Είναι κοινή με όψεις και άλλα προγράμματα, και κρατά τα δεδομένα της μόνο όσο τρέχει το πρόγραμμα. Με επέκταση μνήμης (API 21) κάθε πρόγραμμα παίρνει δική του, που κρατά ό,τι έχει ως το τέλος του, ό,τι κι αν τρέξει στο μεταξύ· το `VX_DATA` λέει ποια ισχύει (A = 1: δική του).
- **Συντεταγμένες:** x σε pixels του mode (mode 0: 0–191, mode 1: 0–383), y από 0 ως 258. Η γραμμή μενού πιάνει τα y 0–11.
- **RASM:** οι ετικέτες δεν ξεχωρίζουν κεφαλαία από πεζά (`BOX` και `box` είναι το ίδιο). Τα hex γράφονται με `#` και όχι με `&`.

## Οι μορφές των δεδομένων

- **Γραμμή μενού** (`VOS_SET_BAR`): `db πλήθος; dw μενού, ...`. Τα κοινά VIEW και HELP τα δίνουν τα `VOS_MENU_VIEW` και `VOS_MENU_HELP`.
- **Μενού:** `db τίτλος, πλήθος` και για κάθε επιλογή `db κείμενο, εντολή, γράμμα, 0`.
  - κείμενο: `VOS_SEPARATOR` για γραμμή
  - εντολή: 1.., ό,τι επιστρέφει το `VOS_UI_EVENT`
  - γράμμα: συντόμευση CONTROL+γράμμα, ή 0
- **Κουμπιά** (`VOS_SET_WIDGETS`, μετά `VOS_DRAW_WIDGETS`): `db πλήθος`, και για κάθε κουμπί `dw x, y; db πλάτος σε χαρακτήρες, κείμενο, εντολή, 0`.
- **Διάλογος** (`VOS_DIALOG` → A = κουμπί, 0 το πρώτο, το ESC δίνει το τελευταίο): `db τίτλος, κείμενο, πλήθος κουμπιών (1–3), κουμπί, ...`. Για κουμπιά, `VM_OK`, `VM_YES` και `VM_NO`.
- **Κείμενα** (`VOS_TEXTS`): τα φτιάχνει το `tools/mktexts.py` από το `texts.txt`, με γραμμές `ΟΝΟΜΑ | English | Ελληνικά`.
  - Δίνει `T_ΟΝΟΜΑ` (`VT_FIRST` = `#C0` και πάνω) και τον πίνακα `texts:`. Ως 64 κείμενα.
  - Το `|` χωρίς κενά γύρω του αλλάζει γραμμή στους διαλόγους.
  - Τα κείμενα μπαίνουν όπου ζητείται «κείμενο» (μενού, κουμπιά, διάλογοι). Με το `VOS_MSG` παίρνεις τη διεύθυνσή τους για `VOS_PRINT`.
- **Παλέτα** (`VOS_PALETTE`): 17 χρώματα firmware (0–26): 16 πένες και το περίγραμμα. Στο mode 1 μετράνε οι πένες 0–3.
- **Ορθογώνιο** (`VOS_RECT`, IX →): `dw x, y, w, h; db πένα`.
- **Εικονίδιο:** 16 γραμμές των 16 χαρακτήρων στο `icon.txt`. Κάθε χαρακτήρας είναι πένα σε hex (mode 0, παλέτα του Launcher) ή `.` για διάφανο. Ο Launcher το διαβάζει από τη δισκέτα: όσο τρέχει το πρόγραμμα, τα 256 bytes μετά το "IC" είναι ελεύθερα για buffers (το PAINT κρατά εκεί τις γραμμές του).
- **Ονόματα αρχείων** (`VOS_LOAD`, `VOS_SAVE`, `VOS_DELETE`, `VOS_RUN`): 11 bytes, `"NAME    EXT"`. Drive 0 = A:, 1 = B:.

## Το API (έκδοση 22)

| Κλήση | Είσοδος → έξοδος | Τι κάνει |
|---|---|---|
| `VOS_EXIT` | — | τέλος, πίσω στην όψη που το ξεκίνησε |
| `VOS_TICKS` | A = 1 / 0 (+ `VOS_PTR_KEYS`) | `VE_FRAME` 50 φορές το δευτερόλεπτο, ή κανένα. Με το `VOS_PTR_KEYS` (2) τα βελάκια και το COPY κινούν και τον δείκτη και κάνουν κλικ |
| `VOS_FRAMES` | → HL (και A τα bits 16–23) | frames από την εκκίνηση |
| `VOS_RANDOM` | → A | 0–255 |
| `VOS_COMMAND` | A = εντολή | οι κοινές εντολές των VIEW και HELP (6–19). Αρίθμησε τις δικές σου εντολές από το `VC_APP` (32) και πάνω, αλλιώς ένα στοιχείο του VIEW ή του HELP τρέχει μια δική σου |
| `VOS_ERROR` | A = σφάλμα | διάλογος σφάλματος |
| `VOS_MODE` | A = 0 / 1 | mode 0 (192×259, 16 πένες) ή 1 (384×259, 4 πένες) |
| `VOS_PALETTE` | HL → 17 χρώματα | |
| `VOS_CLS` | A = πένα | καθαρίζει την οθόνη |
| `VOS_PLOT` | HL = x, DE = y, A = πένα | ένα pixel |
| `VOS_RECT` | IX → ορθογώνιο | γεμάτο ορθογώνιο |
| `VOS_COLOURS` | A = πένα κειμένου (+ `VOS_BOLD`, `VOS_ITALIC`, `VOS_UNDERLINE`), C = φόντου | για τα `VOS_PRINT` και `VOS_CHAR`. Τα στυλ βγαίνουν από την ίδια γραμματοσειρά, για κάθε γλώσσα |
| `VOS_PRINT` | HL = x, DE = y, BC → κείμενο, 0 | |
| `VOS_CHAR` | HL = x, DE = y, A = χαρακτήρας | |
| `VOS_MSG` | A = κείμενο → HL | η διεύθυνση ενός κειμένου (`T_*` ή του συστήματος) |
| `VOS_SET_BAR`, `VOS_DRAW_BAR` | HL → γραμμή μενού | |
| `VOS_UI_EVENT` | (το τρέχον γεγονός) → A | εντολή μενού, κουμπιού ή συντόμευσης, 0 για καμία |
| `VOS_DIALOG` | HL → διάλογος → A | |
| `VOS_INPUT` | A = τίτλος, HL → κείμενο, C = μέγιστο → carry αν ακυρώθηκε | εισαγωγή κειμένου (χρειάζεται C + 2 bytes) |
| `VOS_SET_WIDGETS`, `VOS_DRAW_WIDGETS` | HL → κουμπιά | |
| `VOS_MENU_VIEW`, `VOS_MENU_HELP` | → HL | τα κοινά μενού |
| `VOS_CATALOG` | A = drive → A = αρχεία, HL → λίστα | 16 bytes το καθένα: 11 το όνομα, στο +12 το μέγεθος σε K. Με A = drive + `VOS_CAT_EXT` και HL → `"EXT"`, μόνο τα αρχεία με αυτή την κατάληξη |
| `VOS_FILE_PICK` | A = τίτλος → A = αρχείο, carry αν ακυρώθηκε | διάλογος επιλογής, μετά το `VOS_CATALOG` |
| `VOS_LOAD` | A = drive, HL → όνομα, DE = πού → BC = μήκος | |
| `VOS_SAVE` | A = drive, HL → όνομα, DE = από, BC = μήκος | αρχείο binary, που αντικαθιστά το παλιό. Με A + `VOS_LOAD_IX` (#40, έκδοση 20) η κεφαλίδα του λέει φόρτωση στο IX, όχι στο DE (ένα `.SCR`: IX = #C000) |
| `VOS_DELETE` | A = drive, HL → όνομα | |
| `VOS_TEXTS` | HL → πίνακας κειμένων | τα κείμενα του προγράμματος |
| `VOS_MENU_OPEN` | → NZ αν είναι ανοιχτό μενού | |
| `VOS_KEY_HELD` | A = πλήκτρο → NZ όσο πατιέται | για παιχνίδια |
| `VOS_BLIT` | IX → `dw x, y; db bytes, γραμμές; dw πηγή; db βήμα πηγής` | εικόνα: ζεύγη (μάσκα, pixels) |
| `VOS_SOUND` | A = κανάλι 0–2, HL = περίοδος (bit 15: θόρυβος), C = ένταση 0–15, B = frames | νότα· το 440 Hz είναι περίοδος 142 |
| `VOS_SPLIT` | HL → `dw y1, y2; db 8 χρώματα` (0 = σβήνει) | μικτή οθόνη: mode 0 ανάμεσα στα y1 και y2 |
| `VOS_RUN` | A = drive, HL → όνομα | τρέχει άλλο πρόγραμμα, και μετά ξεκινά πάλι αυτό |
| `VOS_KEEP` | → HL → 16 bytes | μνήμη που μένει ανάμεσα σε προγράμματα |
| `VOS_BANK_GET`, `VOS_BANK_PUT` | HL = από, DE = προς, BC = bytes | αντιγραφή από και προς τη bank δεδομένων |
| `VOS_BACKGROUND` | A = 1 / 0 | συνεχίζει ή παγώνει όταν είναι πίσω από άλλο |
| `VOS_DRAG` | HL = x, DE = y, BC = w, A = h → carry: νέα HL, DE | σύρσιμο παραθύρου από τον τίτλο του |
| `VOS_FIT` | ίδια → HL, DE | φέρνει ένα παράθυρο μέσα στην οθόνη |
| `VOS_EXT` | A = κλήση `VX_*`, BC, DE, HL όπως θέλει → A, HL, C, DE, carry | οι κλήσεις μετά τον πίνακα (έκδοση 15), παρακάτω |

**Οι κλήσεις του `VOS_EXT`:** `VX_VERSION` → A = API, HL = έκδοση V-OS (BCD). `VX_FREE` C = drive → A = ελεύθερα K. Άγνωστη: carry `VX_CLIP_PUT` HL = κείμενο, BC = bytes → το πρόχειρο (ως 1K). `VX_CLIP_GET` DE = πού, BC = χώρος → HL = μέγεθος (έκδοση 16). `VX_M4` HL → εντολή για την κάρτα M4 (db μέγεθος, dw εντολή, δεδομένα), DE → απάντηση, BC = bytes· carry: δεν υπάρχει M4 (έκδοση 17). `VX_MEM` → HL = η RAM σε K, DE = τα ελεύθερα K για προγράμματα (έκδοση 18). `VX_BEHIND` DE → db μονάδα, όνομα 11 bytes ενός αρχείου: το πρόγραμμά του (ανά τύπο) ξεκινά πίσω από αυτό, με `init` A = 3 και το αρχείο στο `VOS_OPEN` (έκδοση 19· το MUSIC το ξέρει). `VX_DATA` → A = 1 αν η bank δεδομένων είναι δική του (επέκταση μνήμης), 0 αν είναι η κοινή bank 4 (έκδοση 21· το NOTEPAD κρατά έτσι κείμενο ως 16K). `VX_DB` C = μια κλήση `DB_*`, DE, HL → βάση δεδομένων (έκδοση 22, παρακάτω).

### Βάσεις δεδομένων (έκδοση 22)

Το `VOS_EXT` με A = `VX_DB` και C = μια κλήση `DB_*` δουλεύει σε μια βάση δεδομένων: ένα αρχείο `ΟΝΟΜΑ.VDB` από σελίδες 1K, όσο μεγάλο επιτρέπει η δισκέτα (ως 255K). Έχει ως 8 πίνακες· ένας πίνακας έχει ως 10 πεδία, κείμενο (ως 255 χαρακτήρες) ή αριθμό (2 bytes), και μπορεί να έχει πεδίο-κλειδί (κείμενο ως 64 χαρακτήρες, ή αριθμό) με ευρετήριο, ώστε το FIND να είναι γρήγορο. Μια εγγραφή είναι τα πεδία της το ένα μετά το άλλο· το id της (rid) είναι ένας αριθμός 16 bit. Μία βάση είναι ανοιχτή τη φορά, για το πρόγραμμα που την άνοιξε. Κάθε κλήση γράφει τις αλλαγές της στη δισκέτα πριν επιστρέψει. Ο kernel φορτώνει τη μηχανή, το `DB.SYS`, από τη μονάδα A: την πρώτη φορά.

| Κλήση | Είσοδος → έξοδος |
|---|---|
| `DB_CREATE`, `DB_OPEN` | DE → db μονάδα, όνομα 11 bytes (`"STREETS VDB"`)· OPEN → A = 1: άλλο αλφάβητο |
| `DB_CLOSE` | |
| `DB_TABLE` | DE → όνομα (8), πεδία, πεδίο-κλειδί (0: κανένα), μετά κάθε πεδίο: όνομα (8), τύπος, μήκος → A = πίνακας |
| `DB_USE` | E = ο πίνακας που χρησιμοποιούν οι παρακάτω κλήσεις |
| `DB_INFO` | E = πίνακας, HL → 124 bytes: η περιγραφή του → A = πίνακες |
| `DB_ADD` | HL → εγγραφή → DE = rid |
| `DB_GET`, `DB_PUT` | DE = rid, HL → η εγγραφή |
| `DB_DEL` | DE = rid |
| `DB_FIND` | HL → κλειδί όπως σε εγγραφή (χώρος για εγγραφή), E = πόσα bytes μετρούν (0: όλα) → DE = η πρώτη εγγραφή με αυτό το κλειδί ή μετά από αυτό |
| `DB_FIRST`, `DB_LAST`, `DB_NEXT`, `DB_PREV` | HL → χώρος για την εγγραφή, ή 0 → DE = rid, με τη σειρά του κλειδιού· carry στο τέλος |
| `DB_COUNT` | → HL = εγγραφές |

Λάθη: carry και A (`DB_ERR_*`, και τα λάθη της δισκέτας), που τα δείχνει το `VOS_ERROR`. Το κείμενο κρατιέται όπως γράφτηκε: μια βάση παίρνει το αλφάβητο της γλώσσας που είναι ενεργή (ελληνικό, ή Latin-1 για γαλλικά, ισπανικά, γερμανικά, ιταλικά) την πρώτη φορά που ένα πεδίο κειμένου παίρνει χαρακτήρα πάνω από 127, και το `DB_OPEN` δίνει A = 1 όταν αυτό δεν είναι πια το αλφάβητο της γλώσσας· τότε δείξε το `DB_ERR_ALPHABET` με το `VOS_ERROR`. Η ταξινόμηση και το FIND συγκρίνουν bytes: κεφαλαία και πεζά, και τονισμένα, είναι διαφορετικά. Παράδειγμα είναι το STREETS (`myapps/streets`), ένας οδοδείκτης· το `tools/vdb.py` δείχνει και ελέγχει ένα αρχείο `.VDB` στο PC.

Πλήρεις λεπτομέρειες, π.χ. για το παρασκήνιο, το accessory και το `VOS_SPLIT`, έχει το `src/api/vos_api.inc`. Για παραδείγματα, δες τα `apps/demo/demo.asm` (mode 0, κίνηση), `apps/clock/clock.asm` (accessory) και `apps/mixed/mixed.asm` (μικτή οθόνη). Ένα ολόκληρο παιχνίδι με sprites, πίστα από αρχείο και ήχο είναι το `myapps/vrouves/`.

Ένας βοηθός AI που γράφει πρόγραμμα πρέπει να διαβάσει το [`AI.md`](AI.md) (στα αγγλικά): οι ίδιοι κανόνες, πιο σύντομα, με τις παγίδες της RASM και της bank δεδομένων.
